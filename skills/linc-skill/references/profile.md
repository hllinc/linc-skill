# linc 工作画像（与产品无关；最后核实 2026-09-17）

## 角色与工作构成
一人横跨多个服务仓库的研发负责人，主线是商业化（计费/订阅/支付/防刷）、增长数据（看板/埋点/成本毛利）和 Agent 运行时。日常按频次：线上问题与数据核查 > 功能交付 > 数据口径 > 方案/需求评审 > 项目管理 > 账号与额度运维 > 团队工具建设。

## 工作方法
- **证据驱动**：业务常识做第一道校验（分母不能小于分子、长周期不能小于短周期）；恒等式对账；一手源优先；失败要显示失败不显示 0；复现是决策前提；自提根因假设让执行者用事实证伪。
- **方案先行**：读需求 → 核评审状态 → 评估矛盾与边界 → 技术方案 → 团队文档 → 评审 → 开工；方案要收敛、要能给人看也能指导 agent。
- **改动收敛**：合并前必问"上线有没有影响、要不要开关、默认值是什么"；跨系统职责边界先画；扩展性不够就重做但不刷历史数据。
- **交付闭环**：新分支 → 本地测试 → 按仓库规则自审 → MR → 本人合并 → 评审意见逐条回修 → 真实环境验证 → 配置逐环境核对 → 部署顺序 runbook → 任务状态流转 + 评论 → 上线看效果 → 复盘回写规则。
- **生产纪律**：只读先行、先备份、先评估影响面、逐项授权、执行后回读；提前备好的配置不重启；灰度 shadow → observe → enforce，但有证据时直接 enforce。
- **协作**：团队正式文档面唯一，原地改不覆盖评论；对产品提问编号 + 默认值 + 追问；对象带名称；建机制而非单点解决（评审机器人、CLI 替代 GUI、真相源表格、把重复动作蒸馏成 skill）。

## 决策风格
- 业务规则自己拍板到字段级；AI 出 A/B/C 他单字选；技术细节授权 AI 定。
- 保守偏兼容：不迁历史数据、分阶段上线、临时方案带退出条件、坏了先回滚止血。
- 对根本正确性不妥协：后验方案直接否掉；资金相关逻辑"不能有半点错误"。
- 成本敏感：先做"立马能做且有效"的，成本高的待定；不引入重三方依赖。
- **会被证据说服**："那还是算了吧""接受建议""那就没有必要每天都有人上线了"——给出成本、数据或更简单的等价方案，他会改主意。

## 反模式（自我校准用）

| 反模式 | 说明 | 更好的做法 |
|---|---|---|
| 单会话过长、多主题混杂 | 数百轮的会话里同一规则被重申 4～15 次；一部分重申是工具上下文压缩造成的，不全是他的问题 | 一个会话一个主题；规则前置进规则文件而不是口头重复 |
| 开题信息极少 | "切""补吧""开吧"靠多轮追问补齐，又讨厌"每节都要我确认" | 用他自己写过的交接稿格式：任务 / 已完成 / 关键事实（不可回退）/ 结论 |
| 同一环境操作靠口头反复纠正 | 一个月内 ≥10 次同一句 | 第二次纠正即沉淀成脚本/skill（他后期已这么做） |
| 需求中途滚雪球 | "对了，刚忘说了""刚想了下" | 开题时给完整口径表 |
| 评审意见人肉搬运，同类问题反复被点名 | 示例配置文件未同步、异常吞并等被评审机器人点名 7 次 | 前置到规则文件 / pre-commit |
| 把 AI 当浏览器操作员 | 整个下午"下一个""点了" | 有 CLI/API 一律用 CLI（他后来写成了团队规范） |
| 明文凭据贴进会话 | 从入职第一周到最近都有 | 凭据只放 .env / secret，对话里只给变量名 |
| 生产写操作授权粒度不一 | 早期先确认，后期直接让 AI 批量建生产账号 | 固定为只读 → 影响面 → 逐项授权 |
| "还是不行"式盲试循环 | 早期最重：单会话 14 轮"还是报错"；11 月起学会回滚/换会话 | 第 3 次就换策略 |
| 设计在实现中反复漂移 | 存储选型、有效期口径删了又加 | 架构选型先写进方案，改口先改文档 |
| 强推共享分支、误合 release 靠 AI 撤回 | 早期偶发 | 分支保护 + 合并只走 MR |
| 同一句连发 2～7 次 | 多为客户端卡顿重发，非行为问题 | 忽略 |

## 演进（2025-09 → 2026-09）
| 阶段 | 特征 |
|---|---|
| 入职首季 | 第一周就改业务代码，环境坑全丢给 AI；先私下建 demo 学新框架；"按官方文档/示例来"压 AI；入职第 5 周就为团队写 tool 开发规范进 AI 规则目录；框架升级踩坑后学会回滚/换会话 |
| 第 4～5 个月 | 单人全栈；"请先向我复述确认你的方案，不要修改""先完善任务系统就行，不要写代码"；任务编号驱动 → 文档 → 自测 → 同步任务系统 → PR；转入支付/计费：默认分布式、幂等、时序、鉴权全环境一致 |
| 第 6～7 个月 | 方案多轮 check；"先测一条数据"；起草 MR 模板与仓库架构红线；分支/MR/"我来合"雏形；"先不要自动提交，我都看不到你修改了什么" |
| 第 7～9 个月 | 收尾模板固化；仓库规则自审前置；对抗性追问方案；验证留痕进 issue；开始 7 小时无人值守委托 |
| 第 10～11 个月 | 数据看板主线；建机制：埋点真相源、CLI 替代 MCP、任务系统迁移、拆任务给团队 |
| 第 12 个月起 | 换到 Claude Code + 流程 skill，AI 成为流水线主驾驶，他做门禁审批："合并 / 批量合并 N / 发布 / 授权"；上线复盘回写 skill；蒸馏个人 skill |

**一直没变的**：复用优先、中文、极短选项作答、粘日志式排障、关键动作自己做、凭据贴进会话的坏习惯。
