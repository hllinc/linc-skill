# Agent 运行时设计手册

> 来源：一位工程师在多模态视频生成 Agent、沙箱运行时、计费门、灰度平台上的项目规范、设计文档与历史会话观察；已剥离所有公司、产品、人名、工单与环境变量名，只保留通用做法。

## 1 分层与职责

1. 系统分三层：Agent 运行时（在沙箱内跑 Turn Loop）、网关（鉴权、计费、灰度、审计、供应商代理）、前端（渲染与用户交互），职责严格单向。
2. 运行时内部再分"核心"与"入口"：核心承载全部产品逻辑，入口层（TUI、WebSocket、IM）只做 I/O 与事件映射。
3. Agent 循环是可替换的引擎基础设施，产品行为只通过上下文变换、流函数、工具钩子、follow-up 与扩展宿主注入，不改引擎源码。
4. 依赖方向固定为 types → 聚合 → 上下文 → agent → 入口，模块之间禁止循环引用。
5. 工具只负责把输入规范化并调用能力，语义判断（用户到底要什么、网页讲了什么）交给模型，不在代码里硬编码。
6. 确认门禁、澄清与"何时问用户"这类行为放在系统提示里治理，先改 prompt 再考虑改代码。
7. 网关是所有授权、定价、供应商选择与公开错误信封的唯一权威，运行时不得自行复制一份业务开关。
8. 沙箱只拿到网关白名单下发的环境值，本地开关在托管环境中天然失效，这是有意的。
9. 多智能体角色（协调者、执行者）先在类型层预留，不到规划明确前不实现路由。
10. 新能力先复用现有工厂、基类、结果构造器，禁止并行造第二套抽象。
11. 官方框架（如 Google ADK）的 session、state、历史消息能力直接用，不自己再写一套。
12. 升级或引入框架前先跑通官方示例，再回到项目里改。

## 2 工具设计

1. 每个工具返回双通道：`content` 给模型（最小必要自然语言），`details` 给前端（结构化 diff、预览、进度）。
2. `content` 必须自包含，模型看不到 `details`，却要能凭 `content` 决定下一步。
3. `content` 禁止返回 JSON，自然语言更省 token 也更稳。
4. 成功不需要 "success" 标记，失败直接 `throw`，由循环统一标 `isError`。
5. 每个工具自己截断输出，再由统一的输出大小守卫兜底。
6. 工具描述内嵌调用示例，用 Builder 生成示例以免影响其他工具。
7. 工具 schema 由类型定义自动生成，类型变化即 schema 变化。
8. 高风险或长流程工具（如视频生成）前置"必须完整读过指南"门，通过 `beforeToolCall` 钩子校验，指南缺失时放行而非阻塞。
9. 长耗时工具持有"租约"并周期刷新，供心跳上报判断进程是否仍活着。
10. 媒体理解只保留一个 Agent 侧入口，底层 ASR、抽帧、转码由网关编排，不暴露成多个工具。
11. 引用解析先把会话/项目内已知媒体（上传、生成、抓取）规范化为稳定 ID，再发给网关。
12. 优先用领域专用工具（时间线、文件读写）而非 bash 拼 ffmpeg 或 cat，用户体验与可审计性更好。
13. 工具不做前置能力判断（如媒体时长上限），让供应商返回能力错误由模型处理。
14. 生成类工具结果登记到统一媒体注册表并打来源标签，后续理解与校验能发现它们。
15. 多段生成先声明计划（总时长、段数），每段带自身索引，并发的兄弟调用才能区分。

## 3 上下文与缓存

1. 上下文是三层合并：用户级记忆 + 项目级记忆 + 会话消息，模型看到合并结果，不知道来自哪层。
2. 媒体预处理独立并行进行，与 LLM 调用解耦，在 prompt 组装前完成。
3. prompt cache 的核心不变量：同一上下文窗口内，追加工具结果或用户消息后，之前发出的输入必须仍是前缀。
4. 每个 MR 都要显式报告"影响/不影响缓存前缀"，涉及系统提示、工具顺序、消息转换、提醒注入、压缩的改动一律算影响。
5. 验证前缀保持要比对至少两轮真实工具调用加一条新用户消息的供应商载荷，单次变换或桩断言不算证据。
6. 一个会话保持一个缓存键，重试也不换。
7. 用量核对：普通输入 + 缓存读 + 缓存写 = 总输入，三桶不相交。
8. 生成产物通过 tool result 进入模型，禁止再作为累积附件重复注入，否则模型会产生幻觉。
9. 累积媒体注入前过滤掉工具生成来源的条目，即便注入当前关闭，也让重开时安全。
10. 压缩用独立的总结模型路由，不继承主模型配置。
11. 压缩触发预算支持绝对 token 或上下文窗口比例，两者都设时绝对值优先，上限只作可选纠偏。
12. 压缩或恢复启动新窗口时要声明冷边界，不假装前缀还在。
13. 上下文占用按（输入 + 缓存读 + 缓存写）/ 窗口计算，不要拿措辞阈值当占用阈值。
14. 历史兼容：老会话里的引导消息保留常量以便恢复时忽略，而不是删掉后让恢复报错。
15. 单会话过长、主题混杂会导致上下文漂移，宁可换会话也不继续在 150 轮里打补丁。

## 4 会话与流式

1. 聊天面板走 SSE/WS 流式，侧栏操作走独立通道，两者不复用一条连接。
2. 断线重连必须带游标，服务端按游标补发，客户端按消息 ID 去重。
3. 游标要判断分段是否已落库：前两段入库、游标在第三段中间时，应从第三段起点重放。
4. 每条流事件带稳定的消息 ID 与结束标记，一次用户 turn 恰好对应一个 `done`。
5. 终止帧发出前先检查是否有排队的 follow-up，需要继续就扣住终止帧，避免"回答完了但任务没做完"。
6. 长耗时工具（视频生成）以 detached 方式后台执行，主会话不阻塞，结果通过事件回流。
7. 确认门禁：额外付费生成前必须弹确认卡，且该轮只能有这一个工具调用，不能与生成并行。
8. 确认窗口失效（模型不等确认就往下走）是最典型的反复回归 bug，根因往往在 prompt 而非代码。
9. 需要用户决策时调用提问工具，不要把问题写在回复文本里结束 turn。
10. 中途状态汇报不应结束 turn，未完成步骤要继续做而不是等用户催。
11. 事件投影 ACK 从"网关发出成功"迁到"浏览器确认送达"要走灰度开关。
12. 客户端消息、运行时命令、事件投递各有独立幂等键与 TTL。
13. 会话重连令牌有租约期，覆盖沙箱 resume 与重连恢复窗口。
14. 网关持久化 turn 协调器有领导者选举、有界认领与无进展超时，避免丢失 turn 悬挂。

## 5 计费门与运行时

1. 先冻结、后结算、失败退还，三段式是所有付费能力的通用骨架。
2. 只有稳定资产登记并写入可恢复检查点后才结算，下载失败不结算，终态失败释放冻结。
3. 检查点之后结算暂时失败时延长租约退避重试，不释放已交付任务的额度。
4. 结算成功但终态写入失败依赖结算意图与账本幂等，不重复扣款。
5. 恢复路径消费检查点：已交付则跳过下载、上传与登记，直接结算。
6. LLM 冻结按输入 token 加少量输出预估，不按模型最大输出冻结。
7. 计费统计以 prompt 缓存口径为输入量，缓存读写不能双算。
8. 定价表是收费价不是供应商价，汇率换算往返必须同一口径。
9. 同目标重试上限按生成目标或分镜链计数，不按工具名计数，目标无法识别就不计。
10. 重试上限先 observe 再 enforce，计数存会话状态并在 agent 结束时重置。
11. 任务完成门：可见文本终止而 todo 仍有未完成项时自动排队续跑，受注入次数、墙钟、上下文占比、todo 快照不变四重约束。
12. 已跑过付费生成的 turn 仍允许续跑，完成模型自己的 todo 不是新的花钱授权。
13. 取消语义：调用方取消永远是 `aborted`，不是可重试的供应商失败；取消后冻结必须退还。
14. 免费用户首个视频可免冻结试用，但要注入 prompt 限制时长并复用原扣费逻辑。
15. 乐观锁写账本不能只重试三次，数据一致性优先于有限重试。

## 6 沙箱与令牌

1. 每次请求时取令牌，禁止在构造函数或工厂里缓存成实例字段。
2. 令牌优先读文件、短 TTL 内存缓存、环境变量仅作回退；网关推送刷新时立即失效缓存。
3. 沙箱 resume 会轮换令牌版本，持旧令牌的进程会被中间件 401。
4. 令牌不能放浏览器路径，认领令牌可以，真正通信令牌不行。
5. 沙箱出站默认关闭公共流量，用白名单放行。
6. 沙箱操作必须走供应商抽象层，禁止业务代码直接调沙箱 SDK。
7. 同步 SDK 调用必须经异步隔离层，async 函数里禁止直接阻塞。
8. bash 工具用进程范围监督器等待并回收所有后代进程，包括重定向输出、setsid 与双 fork。
9. 进程占用记录在监督器异常退出后保留，PID 消失不代表写围栏与刷盘已完成。
10. 正常取消等监督器回收子进程后才算结束，不要直接杀监督器。
11. 挂载会话写入共享监督器文件锁并有超时，超时在改脏标记前就拒绝。
12. 供应商容量或限流错误用有界重试与退避，并有并发许可上限。
13. 沙箱空闲自动暂停、长期未用回收，暂停事件区分空闲、用户与供应商三种原因。

## 7 灰度与策略平面

1. 灰度平台做用户级分桶、进组、曝光、结果回收，部署级金丝雀由另一个系统负责。
2. 客户端对齐 OpenFeature：取详情 + 上报结果，分配与依赖在网关单次 evaluate 内解析。
3. 判定顺序固定：调试覆盖 → kill switch → 过期/生命周期 → 白名单 → 队列 → 固定标签 → 一致性哈希 → 回退。
4. 分流不等于观测：权重决定臂，采样决定是否落漏斗。
5. 盐值实验期内不可改，改权重只影响新分配，老用户保持粘性。
6. 跨 feature 依赖在网关解析，客户端不自行评估上游，依赖未命中走回退目标并仍返回 200。
7. 所有新开关默认 observe，observe 期至少 2 倍令牌 TTL 后才切 enforce。
8. 每个开关同时写明默认值、退出条件与回滚方式，接入时优先设计成可回退。
9. 沙箱创建时 bake 分配结果，改策略后老沙箱不变，需要新沙箱或策略刷新。
10. 策略热切：运行时监听策略漂移，切换后向网关发送确认信标。
11. 曝光与结果落持久化事实源，产品埋点只承载当前分桶属性，精确历史分析要离线 join。
12. 新接口预留必须同 PR 落消费方，无消费方的字段、键、开关不允许合入。
13. 业务控制平面只有一个，不在沙箱或运行时再加重复业务开关。
14. 灰度完成后锁定默认值，保留反向开关只做回退用。

## 8 可观测

1. 系统级 trace 传播是平台默认，业务 span 只在能实质改善排障时添加，且必须门控。
2. 传输级归因（traceparent、request id、session/project id）与业务归因（conversation、tool name、tool call id）分层，后者只在有语义时透传。
3. 框架层自动发出运行时事件，业务代码通过共享执行路径获得可观测性，不手写审计。
4. 运行时事件是单一扁平事实流，专项审计集合只是快照或聚合视图，不做并行事实源。
5. 计费流、控制平面状态、trace、日志、指标各有语义，不合并。
6. 错误信封由首个构造它的组件独占所有权，中继层只能追加关联字段，不得改写或白名单过滤。
7. 本地异常不因带 `code`/`data` 就变成公开信封，保留旧公开文本行为。
8. 公开错误优先携带 trace id、request id、task id，供应商请求 ID 与原始响应体保持内部。
9. 禁止日志或信封中出现 prompt、凭据、签名 URL、供应商原始响应。
10. 退款或降级分支后不再发用量事件，避免零用量污染数据。
11. 结构化日志每行打上运行时发布标识，便于混合版本归因。
12. 心跳事件采样，首个与强制事件不采样。

## 9 协议兼容

1. WS 帧、HTTP 体、NDJSON 行、outbox 载荷、事件类型、字段名与必填性的改动默认向后兼容。
2. 三端不同时部署，新代码必须接受未来 24 小时内仍可能出现的协议变体。
3. 优先新增可选字段，删字段、改必填、改事件类型、改语义都算破坏性变更。
4. 有意跳过兼容时，MR 必须写明原因、影响版本、部署顺序、回滚方案与不兼容窗口。
5. 评审协议改动要逐项检查混合版本、重连重放、pending outbox 重试、历史重放与 24 小时旧数据恢复。
6. 错误码、API spec、服务端错误定义、前端文案四源同步并由 CI 校验。
7. 数据文档只加可选字段，旧进程忽略新字段，新进程能处理无字段的旧记录。
8. 滚动发布中的旧任务没有检查点时按固定键幂等重建，再写入检查点。

## 10 框架升级与依赖

1. 升级 Agent 框架前先查版本矩阵（框架 ↔ LiteLLM ↔ 供应商 SDK），逐项官方确认。
2. 小版本升级也会改变恢复语义、工具调用配对与确认窗口行为，先在隔离环境跑通再进主线。
3. 升级出问题先完全回滚止损，再另开分支排查，不在坏掉的状态上叠补丁。
4. 按官方示例对齐实现，AI 生成的"变通"写法用官方文档压回去。
5. 引擎从 npm 依赖 vendored 进仓后，所有导入走 barrel 出口，禁止直引内部文件。
6. 本地补丁（新增供应商、模型登记、类型扩展）逐条记录在项目规范里，方便下次 regen 对账。
7. 重试统一用成熟库（如 tenacity），参数集中常量，禁止手写 for + sleep。
8. 第三方调用必带超时、重试、日志与降级，非关键路径失败不阻塞主流程。
9. 依赖版本覆盖不混进无关 MR，必须单独说明。

## 11 典型 bug 清单

1. 现象：模型不等用户确认就继续执行 → 根因：确认逻辑写在代码分支而模型 prompt 未约束 → 防御：确认门禁在 prompt 定义并要求该轮只调一个工具。
2. 现象：resume 后所有网关请求 401 → 根因：进程启动时缓存了令牌 → 防御：每次请求读文件取令牌并在刷新推送时失效缓存。
3. 现象：模型描述并不存在的素材 → 根因：生成产物既进 tool result 又被当累积附件重复注入 → 防御：注入前过滤工具生成来源。
4. 现象：回答结束但 todo 未完成 → 根因：可见文本终止直接发 done → 防御：终止前走完成门并排队续跑。
5. 现象：单元测试全绿但压缩从不触发 → 根因：测试桩掉了 dispose，真实链路没跑 → 防御：多步交互必须有断言可观测结果的集成测试。
6. 现象：取消后冻结额度未退还 → 根因：取消路径未走退还分支 → 防御：取消归为 aborted 且强制退还，添加配对测试。
7. 现象：冻结额度与实际扣减对不上 → 根因：按模型最大输出冻结或把整个请求体算输入 → 防御：按实际输入字段与小额输出预估冻结。
8. 现象：SSE 一分钟左右断连、消息丢失 → 根因：无游标重放与去重 → 防御：游标 + 消息 ID + 服务端补发。
9. 现象：灰度实验臂用户仍用旧模型 → 根因：沙箱创建时已 bake 旧策略 → 防御：策略刷新或新沙箱，并在文档写明粘性。
10. 现象：后台任务静默消失 → 根因：create_task 无引用被 GC → 防御：持有 pending 任务集合。
11. 现象：取消时关键清理被二次取消 → 根因：finally 中的 await 未屏蔽 → 防御：shield 或超时竞赛保护清理。
12. 现象：外部调用后冻结与连接泄漏 → 根因：只捕获超时漏掉网络异常 → 防御：同时捕获连接类异常。
13. 现象：本地开发进程写坏共享库 → 根因：消费者组名未按环境隔离 → 防御：每环境独立组名，本地留空。
14. 现象：终态写入两次扣款 → 根因：结算与终态非原子 → 防御：结算意图与账本幂等键。
15. 现象：相同目标被反复重试烧额度 → 根因：无同目标计数 → 防御：按目标链计数、observe 后 enforce。
