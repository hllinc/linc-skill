# Python 服务开发手册
## 1. 项目结构与工具链
- 先找 pyproject、锁文件、包根、入口、settings、migrations、tests 与文档化命令，用仓库既有命令而非自造。
- pytest、ruff、mypy/pyright 与包元数据统一配置在 pyproject；运行与开发依赖分组；可部署服务必须有锁文件；持久化命令不依赖本机绝对路径或隐式 PYTHONPATH。
- 新纯 Python 项目默认用 uv 一站式管理；已有 poetry/pip-tools 项目不在功能开发中顺手迁移，迁移单独立项并验证锁文件等价，CI、Dockerfile、文档一起切。
- 一次性脚本用 PEP 723 内联元数据加 uv run，需复现时必须提交 sidecar 锁文件并让 CI 按锁运行；内联脚本不能引用内部一方包，超过单文件即升级为正式项目。
- 生成代码、vendored 库、迁移输出按仓库既有策略排除在严格 lint/type 之外，不改第三方代码迎合风格检查。
- 分层固定：传输层做框架映射与鉴权上下文，应用层做用例编排与事务，领域层做规则，基础设施层做 DB/Redis/MQ/HTTP/推理客户端；生成代码不手改。
- 注释写不变量与原因，不写会腐烂的状态快照；生产代码禁用 spike/minimal/temp 等临时性命名，过渡脚手架必须写明退役条件。
- 升级共享依赖要改遍所有消费方（含可编辑路径安装与独立 pin 的传递依赖），保持 pyproject、锁文件、`__version__` 一致，跑全量测试。
## 2. Web 框架与路由
- FastAPI 按特性边界拆 router，请求/响应用 Pydantic 模型，依赖函数只做请求作用域依赖，共享客户端在 lifespan 组装与清理。
- Flask 用应用工厂与 blueprint，视图保持薄，业务下沉到 service；避免不可替换的进程级全局状态。
- header、query、body、下游调用里的身份、租户、owner、creator、权限字段一律视为客户端声明，须从认证上下文或权威服务解析。
- 写路径以解析出的认证身份为准：覆盖客户端字段或拒绝不一致，禁止把认证身份当作"信任请求字段之后的兜底"。
- 修鉴权/权限 bug 时，搜遍同一信任类别的所有入口与传播点：header、body、query、path、生成的 schema、服务默认值、仓储入参。
- 鉴权、权限、能力、profile 解析错误必须在副作用前 fail-closed，并有对应测试。
## 3. Schema 校验
- 公共 API 请求/响应模型必须显式，不直接返回原始 provider 载荷；持久化模型与公共 schema 不同时必须分离；语法校验在边界，业务规则在 service/domain 层。
- 有限域值（市场、状态、来源、渠道等）定义为领域自有 Enum/Literal 加唯一解析/规范化函数；传输枚举、DB 字符串、生成客户端值只在边界转换。
- 跨服务/包/存储的有限值放在仓库允许的最小共享包；不得出现大小写、默认值、未知值行为不同的平行枚举集。
- 临时重复使用必须加带任务号、owner、截止日、原因的 finite-value-debt 标记并登记合并任务；缺任一要素即不合规，标记不等于架构批准，无批准不得合入。
- 领域代码深度依赖传输枚举须有可追溯的架构批准记录，且引入该批注的同一 PR 必须带 CI/grep 检查，"以后再加"不算。
- 已发布 schema 默认向后兼容：只加可选字段或版本化行为，删字段、改必填、改名、改枚举含义、拒绝旧合法请求需人工批准破坏性风险评估。
- 模型库按边界选：API/配置/不可信输入用 Pydantic，内部不可变值对象用 frozen slots dataclass，msgspec 只在有性能证据时用；一库包打天下是坏味道。
- 生成客户端先改源契约再重生成；兼容变更测新旧客户端/服务端交叉，破坏性变更测旧路径按预期失败与迁移路径可用。
- 测试覆盖校验错误、默认值、可选字段、枚举与未知值、边界转换、兼容敏感字段。
## 4. 错误处理
- 每个服务只有一套规范错误映射，内部异常只在传输边界转换。
- 预期业务失败用类型化领域异常抛出，禁止用 `(data, err)` 元组、None 加消息、`{"success": false}` 字典在边界模拟错误。
- "边界"按行为判定：返回值会被序列化进 HTTP/RPC/WS/任务终态响应的代码就是边界，改名叫 domain 不能豁免。
- 日志可保留原始异常，API 响应不得暴露堆栈或密钥。
- 校验错误算客户端错误，依赖故障按重试/降级策略分类；分类正确在先，重试策略在后。
- 已发布响应封套与错误载荷的字段、状态码含义、业务数据位置默认稳定，改动需人工批准加兼容、灰度、回滚计划。
- 跨 gRPC/HTTP 传播类型化错误：gRPC 用 Status details 携带结构化信息而非把 JSON 塞进 message，HTTP 用 `{code, message, data}` 封套，裸异常不得穿越边界。
- 客户端从协议通道还原类型化错误以便按 code 分支；解析 message 文本只作兜底，未知形状包装为传输错误并保留原因。
- 业务错误码范围全组合统一分配，越界在注册期失败；封套消息单一语言，翻译在网关或前端按 code 做。
## 5. 依赖客户端
- 客户端通过显式 provider 或启动装配创建；import 时或模块级客户端必须可被依赖覆盖或 lifespan 替换，可能做网络 I/O 的初始化放在启动阶段。
- 可选依赖的"绝不拖垮调用方"适配器要捕获 `Exception`（不只 ImportError）但不吞 `BaseException`，并测试导入即抛的路径。
- 每个客户端设定超时、重试、base URL、凭据、UA 与可观测标签；校验状态码与响应 schema；provider 异常包装为规范错误；提供 fake；关闭异步客户端与连接池。
- 包装层负责 deadline 传播而非固定超时策略，但每个生产调用都要有有界有效期限：调用方无 deadline 时用环境配置的最大兜底，长连接流可豁免请求期限但仍需空闲超时、心跳、有界重连。
- 所有外部入站 deadline 先按平台上下限裁剪再传播；HTTP 无原生在线 deadline，跨跳需显式头契约且入口剥离调用方自带头；每次重试前重算剩余预算，不够覆盖尝试加退避加清理即跳过。
- 按对象生命周期维护的注册表禁止用 `id()` 做 key；优先 WeakKeyDictionary，但要求 key 可哈希可弱引用且身份相等，值不得强引用 key，关闭时确定性删除，closed 标记与状态同一临界区且挂在对象本身。
- 适配器/fake 边界用 `typing.Protocol` 结构化类型，不为每个具体类发明 ABC 接口；需 isinstance 时用 `@runtime_checkable` 并视为浅层守卫。
- 服务发现、密钥、动态配置包在类型化 provider 后，键名与后端载荷形状不泄漏到路由或领域代码；热配置只在可接受陈旧时做有界 TTL 缓存并暴露命中/错误指标；watch 回调要恢复异常、原子更新、关机时干净停止。
- 对象存储写入附带来源服务、环境、request id、归属、保留期元数据；迁移工具先定覆盖策略，输出可重放的成功/错误/冲突记录，签名 URL 必须有期限与作用域且不完整记日志。
## 6. 异步与 worker
- `asyncio.gather` 必须用信号量、池或队列限流；用 `asyncio.timeout` 或框架超时；`to_thread` 只用于有界阻塞调用；CPU 重活不进事件循环。
- 3.11+ 扇出默认用 `TaskGroup`，子任务失败会取消兄弟；仅当"部分成功且相互独立"是契约时用 gather，并配限流与单任务超时；共享期限时在外层包 `asyncio.timeout`。
- 外层超时与兄弟失败并发时收到的是 ExceptionGroup 而非干净 TimeoutError，要用 `except*` 同时处理 TimeoutError、领域错误与兜底 BaseException；绝不吞 `CancelledError`，清理后重新抛出或只捕 `Exception`。
- 必须超出请求生命周期的工作不能放在请求的 TaskGroup 或 timeout 内，但也不能 fire-and-forget：注册到应用级 supervisor/持久队列/持强引用的任务注册表，有自己的有界 deadline。
- 所有生产脱离式执行（task、thread、executor、任务体）经同一个共享防火墙包装：捕获、带 trace id 记 traceback、计失败指标；覆盖率用检查单或 lint 保证。
- "进程能扛住这个异常"的严格回归证明是子进程退出码测试；supervisor/全局不变量任务则相反，要断言其主动变为不可用或非零退出。
- 超出请求的旁路（审计、账本、用量、通知）四件套：只重挂关联字段不整体回放上下文、在持久提交成功或同事务 outbox 行处才脱离、不可回滚的外部效果先按次预留、有界队列、接收与排空串行化的关机顺序、损失策略匹配数据类别（账单类无重建源时用 outbox 或背压而非丢弃）。
- worker 要幂等重试，包含异常处理、日志、指标与重试/丢弃决策，用户可见工作要落进度与终态。
## 7. 后台任务与状态机
- 任务定义类型化载荷、幂等键、有界重试与退避，区分可重试、丢弃、隔离、终态失败；单例任务用锁或调度器保证；长工作不藏在同步请求后，返回任务 ID 或状态 URL。
- Celery：默认早 ack 会丢任务，`acks_late` 需配幂等任务体并明确 `task_reject_on_worker_lost`；可见性超时必须大于最长任务加退避；长任务设 `worker_prefetch_multiplier=1` 并用 `max_tasks_per_child` 回收；beat 只跑一个实例或加分布式锁。
- 事务内入队是双写：要么走与业务写同事务提交的 outbox，要么提交后入队并记录崩溃窗口的对账路径；先入队后提交时 worker 必须重读持久状态。
- 状态用领域 Enum 定义并标明终态，允许的转换集中在一张表或一个策略函数；终态拒绝普通处理与失败转换。
- 启动后台工作、排队昂贵处理或生成外部产物之前先创建持久任务行，崩溃必须留下可检查可修复的记录；进度与状态分开存。
- 转换用 compare-and-update 检查 rowcount、`SELECT FOR UPDATE` 或 Redis 锁守卫；lease 持有者标识必须到实例级（pod 加 pid 或随机 id）。
- 锁不等于围栏：租约下每次持久写都带围栏检查（单调 token 或 owner+version CAS）；外部副作用走 intent-then-execute 并绑定幂等键，provider 不强制幂等键时诚实标注为至少一次并记录重复窗口。
- 同一转换内所有时间戳来自一次捕获的 now，上游给的时间按收到值记录；外部响应先按 schema 解析再映射，畸形载荷变成规范失败转换。
- 修复型定时任务需要名称、间隔、分布式锁键与租约、每轮最大批量、最大执行时间，基于持久 `updated_at` 选窗，修复前重读状态，输出扫描/认领/修复/跳过/锁冲突/失败/耗时指标。
- 测试非法转换、重复事件、双认领单赢家、已终态、重试阈值、取消、异常转失败、完成事件幂等、过期 lease 的旧 worker 被围栏拒绝、修复任务重复运行幂等。
## 8. Redis 缓存与锁
- key 构造器与 TTL 常量集中在一个适配器，隔离敏感的 key 带租户/用户/资源作用域；客户端设超时、同步/异步与调用路径匹配，经依赖装配或 lifespan 创建并在关机时关闭。
- 锁用唯一值加 compare-and-delete 解锁，超过一个租约的工作用 compare-and-expire 续期，取消、超时或达最大租约时停止续期。
- 按模式删除用 SCAN 分批并有上限、可观测与无匹配/大匹配测试；集群下 SCAN 逐主节点遍历，多键操作、MULTI/EXEC、Lua、pipeline 必须用哈希标签共槽并把约定写在 key 构造器旁。
- 复合原子操作用 Lua、事务或成熟库而非读改写；返回值显式定义成功、比较失败、键不存在三种含义；脚本启动时预加载，缓存丢失时重载并只回退一次同时打点。
- JSON 缓存值校验解码与 schema，畸形按产品风险视为损坏或 miss；缓存 miss 不得绕过鉴权与数据完整性检查；失效靠近写或显式事件。
- 幂等存储区分 pending、completed、duplicate、retryable-failure；pending 短 TTL 或 owner 租约，completed 存满去重窗口；高风险路径在 Redis 不可用时计数器 fail-safe。
- 持久副作用禁止只靠 Redis/TTL/内存/进程级去重，可审计、可计费、外部已确认或难回滚的用持久幂等或状态机。
- 防击穿三件套：单飞（进程内 per-key 锁加跨进程 SET NX PX）、区分 miss 原因的负缓存、写入时加 ±10-20% TTL 抖动；极热数据前置短 TTL 本地缓存并用 Pub/Sub 或 CLIENT TRACKING 协调失效。
- 非回环 Redis 必须 TLS，托管 IAM 鉴权用按连接取新 token 的回调并在到期前轮换；应用账号用最小 ACL 命令集，连接串不带密钥进日志。
- 只对瞬时错误（连接、幂等读超时、LOADING、BUSY）重试，有界次数、指数退避加抖动、总期限；每个上游身份配熔断，开路时不重试；持锁重试走续期而非重获，幂等存储重试把 duplicate claimed 视为成功。
## 9. SQLAlchemy 与迁移
- SQL/ORM 只出现在仓储或数据访问模块；会话归属显式，调用方知道自己是否拥有 commit/rollback；多步写用 `session.begin()` 或统一工作单元。
- 新关系型服务默认 SQLAlchemy 2.x 加 Alembic，Django 由框架接管；新 MySQL 异步服务优先 asyncmy，已有 aiomysql 不为合规替换，一个服务边界内不混两种驱动。
- 索引、唯一约束与查询过滤要对齐 API 访问模式；`index=True` 不算证明，复合、部分、函数索引与排序必须体现在已评审迁移中；热路径用编译 SQL 或 EXPLAIN 断言计划。
- 前导通配 like、宽 or、大 in、join 上 distinct、offset 分页需有基数上限文档、计划测试或独立搜索/keyset 路径；索引提示必须有迁移证据。
- Postgres 新服务优先 psycopg v3 统一同步/异步；asyncpg 只在纯异步且有性能证据时用并记录双驱动边界；psycopg 在事务池化代理下要关闭服务端预编译（`prepare_threshold=None`）或改会话池。
- `AsyncSession` 绑定单循环单任务：不跨 gather/TaskGroup/后台任务共享，不传给超出请求的协程；同步驱动在异步路径用 `to_thread` 加独立同步引擎；提交后要读属性用 `expire_on_commit=False`；请求级会话由 yield 依赖开关。
- 每进程 `pool_size + max_overflow` 由全局连接预算（DB 上限、代理上限、预留量的最小者）除以副本乘进程数得出，并发数是需求信号而非池大小；`pool_recycle` 短于代理空闲超时；设 `pool_pre_ping`；事务池化下避免 SET LOCAL、服务端游标、LISTEN/NOTIFY、跨语句咨询锁。
- DB 与 Redis/MQ 双写用 outbox：同事务插入 outbox 行，独立 relay 至少一次发布，消费者幂等；未发布行需告警，失败数与最老待处理龄是一等指标。
- 读写分离按角色维护独立 session 工厂，写与写后读走主库，只有纯读走从库；同请求内"读己之写"保持写一致窗口；从库用只读账号。
- 开事务时禁止做外部 HTTP、推理或长上传；配置 `statement_timeout` 与 `idle_in_transaction_session_timeout`，事务时长做直方图告警。
- 迁移自动生成后必须评审编辑并注明索引、约束、数据风险、回滚与锁影响，与模型、仓储改动同一切片；CI 跑 `alembic upgrade --sql` 渲染计划评审，跑 autogenerate check 检测模型漂移，对空库与上一版本 schema 都回放；数据迁移与不可逆操作拆开评审；merge heads 必须人读。
## 10. 审计历史
- 记录 actor、服务身份、资源作用域与 id、稳定操作名与类型、request id、trace/log id、时间戳、结果与规范错误码；需要时存安全的前后摘要或字段级 diff。
- 禁止存原始密钥、token、密码、签名；参数经脱敏 helper 序列化，不整体 dump 请求响应。
- 关键操作的审计写入与状态变更同事务或同 outbox；尽力型审计仅限明确非关键路径，写失败要捕获、记日志并打失败指标。
- 查询接口需资源作用域鉴权、分页、时间范围过滤与读时脱敏，默认排序确定性；大表在高量上线前定好分区、保留或归档策略。
- 测试脱敏、关键写回滚、尽力写失败可见性、异常恢复、分页、作用域过滤与时间边界。
## 11. 通知
- 每个投递 provider 包在 `send(message) -> Result` 的 Protocol 后；请求带 deadline、content type、状态码校验与响应体大小上限；空批量视为 no-op；响应解析为成功/可重试/永久错误。
- 可配置的出站 URL 是 SSRF 面：限制 scheme 与端口，解析一次并校验 IP 不在私网/链路本地/回环/云元数据段，然后连接同一个已校验 IP（Host/SNI 用主机名），每次重定向重跑校验或禁用重定向，优先经受限出口代理。
- 消息包含类型、接收方引用、模板 id 与版本、actor 或服务身份、trace id、安全摘要与去重键；模板用类型化变量渲染，脱敏密钥与大载荷。
- 关键投递用带重试数、下次重试时间、终态与最后错误的 outbox 或持久队列并在优雅关机时排空；尽力型告警异步跑但必须经防火墙包装并打点；有界并发加退避，按稳定指纹合并重复告警。
- WebSocket/SSE 先认证并解析 app、租户、用户再接受连接；连接注册表按最小投递作用域并发安全，断开经 finally 清理。
- 首连或缓存 miss 时从持久存储重建初始状态，先发快照再发版本化增量；未读计数缓存显式 TTL 与原子递增，缓存缺失不得产生持久计数副作用；消费者对已断开客户端在持久化成功后视为 no-op。
- 测试空批量、超时、非 2xx、畸形响应、重试分类、脱敏、模板、去重、限流、关机排空、SSRF 边界（含 DNS 重绑定 pin）、实时连接重复/断开/冷启动/关闭 socket 写失败。
## 12. 批处理产物
- 破坏性或大范围更新必须有 dry-run；大任务分块、检查点与续跑；限制并发与外部依赖速率；部分失败写错误报告；产物路径、对象键、保留期与下载权限显式。
- 导入每行建类型化行对象（行号、来源、原始值、规范值、错误列表）；行解析前先校验文件类型、大小、sheet 数、表头形状、起始行与列数上限，边界统一规范化单元格。
- 静态校验累积行错误不整文件失败，跨行校验标注所有受影响行，外部名称到 ID 的映射 miss 成为行错误；只提交合法行并保留每行结果，任务记录按状态机落库。
- 错误报告保持原始行序，流式写出，上传对象存储并只存对象键或签名引用，空报告显式表示，不含敏感原始载荷。
- 导出用游标或 id 窗口分页而非 offset，流式写出，沿用 API 读的鉴权与作用域过滤，长导出作为带进度与产物状态的任务。
- 游标迁移先探 min/max 并持久化块边界，目标端幂等写入后再删源端且只删已成功窗口，进度尽力而终态必须持久或可重放。
- 测试空文件、隐藏 sheet、坏表头、长短行、重复行、映射 miss、部分成功、报告生成、切片幂等、取消、崩溃后重试、游标边界含义与部分块重放。
## 13. 回放比较
- 回放任务持久化状态、目标、配置版本、各类计数、超时、并发、限速与保留期，用有界带 deadline 的 worker 执行；只保留白名单 header，绝不盲目回放凭据，捕获载荷先脱敏再存并限制大小。
- 回放目标不得提交副作用，除非按环境/泳道隔离或显式 dry-run；DB 回滚只隔离本地写，webhook、消息、支付、其他数据存储需各自隔离或 stub。
- 比较器定义为 `compare(original, replay) -> Result` 的 Protocol，按方法、路由、内容类型或 schema 版本选择；通用 JSON 比较器先规范化 JSON 字符串、模型、dict、list 与标量。
- 忽略字段只按文档化的精确路径且来自配置或注册，不硬编码在通用比较器；支持容差、无序集合、时间戳、生成 ID、近似数值的自定义字段比较器。
- 差异记录含字段名、路径、原值与回放值摘要、差异类型、分数、忽略标记与元数据，摘要有界；汇总含比较字段总数、差异数、相似度、阈值、比较器名与版本；区分缺失、新增、类型、长度、值不匹配与自定义比较。
- 测试 None 组合、JSON 字符串规范化、模型转 dict、数组长度、缺键、数值容差、忽略字段、自定义比较器、阈值、脱敏、存储分页与回放取消。
## 14. AI 服务接线
- provider 适配器与路由处理、领域编排分离，提示词策略与模型路由不在此层编码；按需加超时、重试、限速、熔断/背压与成本用量日志；provider 测试用 fake，真实调用显式打标。
- 流式处理带取消、心跳与终态错误事件；请求、响应、引用与审计元数据只按产品隐私规则持久化；本地 CPU/GPU 推理隔离并发与内存上限。
- 同一会话有在途轮次时在边界 check-and-claim（锁或幂等标记）并返回类型化 busy 错误，不把两次生成交错进一个会话状态。
- 长流按定时器持久化部分状态（部分转录、token 数），崩溃可续或至少可计费；节奏是产品决策，机制在此。
- 流读取器在每条退出路径（断连、deadline、终态错误）确定性关闭，否则连接泄漏到池耗尽。
- token/成本在完成后或终态失败时带部分计数记录，绝不只在开始时记，并绑定日志同一 request/session id。
- 流终态显式区分 completed/cancelled/provider-error/resumable，消费者才不会重试不可续的流。
## 15. 公共 API 安全
- 认证中间件的旁路列表显式且小；签名校验需要原始 body 字节时先保留，否则先认证再解析领域载荷；每请求不改全局认证设置。
- 只提取定位校验材料所需的不可信选择子（app id、key id），加载配置，校验 token/签名，再解析身份与授权作用域；返回规范认证错误，详细原因只进日志。
- 应用凭据模型存 app id、密钥/公钥引用、来源限制、允许作用域、集成身份、状态与轮换元数据；密钥密码学随机生成且不进日志、测试、文档、生成文件与 fixture；支持禁用与轮换；动态配置短缓存并对未知/禁用/过期/畸形 fail-closed。
- 签名数据先规范化，签名载荷含时间戳与 nonce 或 request id；状态变更 API 与回调强制时间窗与重放防护，只有明确只读或已幂等的调用可豁免并写明理由；MAC 比较用常量时间；新集成用 HMAC 或非对称签名。
- 客户端提供的租户、owner、actor、creator、账号、权限、资源字段都是声明；写路径以认证身份为准并在领域逻辑前拒绝或覆盖；解析出的作用域进类型化请求上下文并写入缓存键、幂等键、限流、日志与审计。
- 作用域检查旁路必须是带审计日志的显式配置，不是 handler 里的隐藏分支。
- 回调在副作用前校验签名/token、时间戳、事件类型、资源 id 与载荷形状；provider 事件码在边界转内部枚举；预期重试时先持久化回执或幂等标记；空载荷、未知事件、坏签名默认按永久失败。
- 高风险路径（金钱、配额、权限、租户隔离、隐私）不确定即 fail-closed，缺租户/actor/资源作用域直接拒绝而不默认，除非是单独批准的 bootstrap/seed/维护路径。
- 生产高风险能力缺配置时保持禁用或启动失败，绝不静默切到本地/测试默认值。
- 单测签名规范化、时间戳过期、重放、作用域；对每个输入面加 owner/actor/tenant/creator/权限/资源伪造测试；副作用前 fail-closed 测试；重复投递、畸形载荷、未知事件回调测试；fixture 用假密钥，沙箱/真实回调测试放显式集成标记后。
## 16. 可观测实现
- 日志带 request id 与 trace id，聚合环境用结构化 JSON；对 Web 框架、HTTP 客户端、DB、Redis、队列与推理调用启用自动埋点；按部署需要提供 health 与 readiness。
- 服务名、环境、区域/泳道、进程组、pod/host、版本等运行时基础属性在 recorder/provider 层加一次，特性代码只加操作特定属性；OTel resource 启动时配置一次。
- 指标标签低基数且有界：禁止原始路径参数、用户 id、request id、prompt 文本、provider 载荷值、自由文本错误串；高基数细节进日志与 trace。
- 指标名形如 `{category}_{operation}_{suffix}` snake_case，定义在一个集中模块，handler 内联字面量算回归；RPC/HTTP 指标用组合统一的 caller/callee/env/method/err_code 基础标签集，新标签过基数评审。
- 日志器包装为上下文感知，自动带 trace id、span id、trace flags 与 log id，调用方不手传；warn/error 级同步 `span.add_event`，span 状态只在逻辑错误边界置错。
- 异步用 contextvars 携带日志上下文；`create_task`/gather/后台任务在创建时捕获 OTel 上下文并在子协程内 attach/detach，否则子 span 不挂父 trace。
- DB/Redis span 属性按 OTel 语义约定并脱敏，不把原始 SQL 或 key 载荷当属性；长连接与 SSE/WS 按消息结束 span 而非一个连接一个巨型 span。
- 不记密钥、token、原始 PII 与完整 provider 载荷。
## 17. 测试与质量
- 默认目标快速、确定、不依赖真实 DB/Redis/MQ/服务发现/云凭据/内网端点/模型服务；基础设施依赖测试放显式 marker、环境变量、独立 target 或独立 CI job。
- 用 marker 区分 unit、integration、API、contract、E2E、live-infra、failure-mode、drill；按仓库配置用 pytest-asyncio；固定 sleep 替换为条件等待，并用 lint 禁 `time.sleep`。
- 仓库用 Bitable 跟踪用例时：加测试前 grep `pytest.mark.tc` 与 sidecar 映射查已有覆盖；删测试前跑废弃级联——列测试导入的产品模块、全仓找非测试 caller、零 caller 同 commit 删模块加测试、有 caller 保留测试；动态 import、反射、装饰器注册需人工查注册表。
- 单测覆盖校验、领域规则、配置解析、缓存键、重试决策、错误映射、幂等决策、授权作用域解析；负路径含缺字段、坏配置、禁止 actor、作用域不匹配、重复幂等键、依赖超时、畸形下游响应。
- 有限值测试用领域符号或边界转换 helper，原始字符串只允许在名字含 boundary/conversion/wire/storage 且带哨兵注释的边界转换测试里，该文件不得断言业务状态且必须有 lint/grep/检查单阻止其导入 service/仓储/工作流层；覆盖全部已知值加至少一个未知值与默认输出；同 PR 迁移或标记 debt，不合规即阻塞。
- 异步代码测取消、更短父期限、有界 worker 数、重复启动、异常恢复与终态；API/契约测试断言响应形状、规范错误码、认证失败行为、schema 行为与向后兼容默认值。
- fake 客户端覆盖成功、传输错误、超时、非 OK 域状态、畸形响应、可取消的慢响应、重复投递；DB 测事务、迁移形状、分页、唯一/幂等约束；Redis 测 TTL、miss 与故障区分、锁失败、CAD 解锁、租约过期、幂等状态；队列测重复投递、重试/丢弃/死信、顺序、并发、优雅关机、重放可见性。
- 高风险路径的真实依赖/E2E/live 测试是发布阻塞证据，要同时断言调用方结果与持久后端结果；门禁不可用时记录已尝试补救、残余风险与解锁动作；真实流测试失败走根因诊断，不改成 mock 断言。
- schema/客户端/迁移/模板/清单变更后跑生成与检查命令，生成物要么干净要么被有意评审；迁移证据覆盖升级、回滚、回填顺序与新旧读写方兼容。
- ruff 作为 lint+format+import 排序默认工具，退役 Pylint 前先审计其深度语义分析、死代码、设计坏味、重复代码检查缺口；ty 仍是 Beta，只作非阻塞旁路 job 试点，不替代 mypy/pyright 门禁。
## 18. 功能 playbook
- 开工前完成足以评审的分析与计划：低风险单包改动可用简短内联计划，多文件、契约可见、数据/schema、异步、发布、bug 修复、风险不明的工作要有任务拆分、验收检查、验证命令、回滚或停止条件与交接方。
- 步骤固定：定位项目根与命令 → 定义契约（Pydantic/OpenAPI、序列化器、生成客户端或 protobuf） → 定义状态变更（模型、迁移、仓储、事务、缓存、队列、产物） → 实现用例（路由薄、决策在 service/domain） → 加聚焦测试 → 跑仓库质量命令。
- 内部服务间调用默认 RPC/gRPC，选 HTTP 时也走平台客户端包装（发现、鉴权、deadline、重试、日志、指标、追踪、契约测试），不把 HTTP 当本地捷径。
- protobuf 在范围内时先记录服务名、IDL 源、生成命令、产物版本、框架绑定与 JSON/二进制策略，任一未确认即阻塞；使用共享生成产物，不建服务本地私有 IDL 副本；生成传输类型在边界转换，领域代码不依赖它们。
- 手工构造生成的请求/响应 DTO 或改写 base/LogId/caller 等身份字段的 diff 必须过实现填充检查；对未认证调用方自报身份做授权是即时阻塞发现。
- 新端点：先改 schema 再接路由，handler 薄，把解析后的鉴权上下文传进 service，加成功与规范失败的契约测试。
- 新仓储/DB 变更：模型与迁移一起设计，事务范围显式，加回滚与错误路径测试，验证分页与唯一/幂等。
- 新缓存/锁/幂等路径：定义 key 命名空间、作用域、TTL、miss/错误行为、CAD 解锁，测过期与重复提交。
- 新队列/worker：先定义载荷 schema、重试/丢弃/DLQ、幂等键、并发上限、优雅关机、指标与重复投递测试，再写业务逻辑；生产者/消费者包装集中元数据传播、路由配置、worker 规模、异常恢复、排空生命周期与 DLQ 可见性。
- 新外部/服务间客户端：类型化请求响应、鉴权/签名头、超时、重试、错误映射、trace 传播、fake 与 live 契约标记同一切片交付。
- 禁止：API 边界用未类型化 dict、隐藏全局客户端或 import 时网络 I/O、把 live 依赖测试混进默认快速套件、把来源示例的业务名词复制进通用规则；写重试默认不安全，只有持久幂等键、唯一约束、状态机或去重表才允许自动重试。
