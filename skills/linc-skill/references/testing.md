# 测试手册（展开）

本文件展开 SKILL.md §3.3"测试先行"与 §1.9"回归证据"：怎么选层、怎么写、怎么证明测试真的在断言。第一部分按测试层与数据；第二部分按写法、CI 稳定性、变异走查、架构适应度、非功能场景、团队测试标准。

# 测试手册·第一部分

## 1. 单元测试
- 行为不依赖真实基础设施即可证明时→写单元测试：领域规则、校验/权限判定、DTO 映射、错误包装、配置解析、重试/回退决策、缓存键/幂等键/锁值构造、状态机迁移、带取消的小并发单元。
- 前端组件层覆盖渲染、props/state 变化、校验提示、空/加载/错误态、权限控件、事件、可访问性角色与键盘焦点；路由/上传/响应式/跨页留给 E2E。
- 先围绕要保护的风险写骨架：命名场景、期望行为、为何重要；用 Arrange/Act/Assert 或 Given/When/Then。
- 输入输出矩阵用表驱动；负路径显式测：缺字段、畸形输入、越权、重复幂等键、超时、已取消上下文。
- 依赖用小型手写 fake；fixture 最小化并按场景命名；只断言行为，不断言日志或私有调用。
- 修 bug 或改可见行为时，先让聚焦测试失败再改实现。
- 禁止：单测里连真实 DB/Redis/MQ/网络；对无序数据做大快照；用 sleep 等异步（改用假时钟/条件轮询/join/channel）；能抽接口就不 monkey patch；用生产大 payload 当 fixture。
- 过关：报告聚焦命令与结果（改动包测试、类型检查、具体用例名）；故意不写单测要说明为何只能在集成/E2E 层证明。
- 硬性门禁：
  1. 单测零真实外部依赖。
  2. 缺陷修复必须先红后绿。
  3. 断言行为而非日志/私有调用。
  4. 不用 sleep 等待并发。

## 2. 集成与契约测试
- 声称"兼容/实现/匹配/对接"任何非己方契约时→至少用一份对方真实产出样本跑过实现；手搓 fixture 只证明"符合自己对文档的理解"。
- 一份样本只覆盖它触及的形状；整契约声明需按变体×角色×方向×操作逐格标 exercised/unexercised；入站格用回放对方样本，出站格只有对方验证器/一致性套件/沙箱接受才算，绝不为取证向真实对端发写操作。
- 拿不到样本→记"real-sample 不可得"及尝试过的补救，声明降级为"符合文档契约"。
- 真实样本是不可信 payload：先授权再抓取、在无出口/无遥测/无凭据的隔离路径上检查与首次运行、静默一次不等于安全、只有脱敏最小化 fixture 能进正常路径、原始字节用完即销毁或按授权期限保留，提交前再过密钥/PII 筛查并保形替换。
- API/契约：IDL 变更后生成代码可编译；断言路由、状态/错误信封、未知枚举、默认值、校验错误、向后兼容（旧客户端读新响应、新服务收旧请求）；批准的破坏性变更要证明两面；"grep 没找到旧字段"不算证据。
- "未设置"只能在线上/渲染层证明；字段可见性按响应形状逐表面断言，全局集只放绝不公开的字段；错误路径注入合成密钥断言不出现在任何返回串或日志。
- 跨仓字段变更五步：生产者兜底/桥接、每个映射器显式保留、覆盖全部消费者变体、一帧真实入站+一条未改路径做对照、按消费者先容忍→生产者发出→清理的顺序落地。
- 架构测试：依赖方向、禁止导入、分层、schema 漂移、生成代码干净；中间件链序、DI 图实例化冒烟、动态配置监听器崩溃恢复/原子更新/取消退出、网关 panic 输出稳定错误码且栈只进日志。
- 数据库：迁移、事务、回滚、upsert、分页、唯一性、分片路由；需要真实方言/事务语义用真实容器，纯单测不用；断言持久化状态与事务边界；性能/索引测试必须有预算/执行计划/行数/确定顺序，只打印耗时是诊断不是门禁；分片 SQL 正反例齐全；async 会话不跨并发子任务共享；outbox 部分失败、读写分离路由、长事务超时均要覆盖。
- Redis：TTL、缓存缺失 vs 基础设施错误、锁获取失败、compare-and-delete 解锁、幂等窗口全状态、滑动窗口边界、streams 续读/清理/重复、模式删除不误伤、防击穿单飞、集群 CROSSSLOT、TLS/IAM 拒绝、重试+熔断各态。
- MQ：解码、重复投递、幂等、重试/跳过/死信、顺序假设、并发、激活门；断言发出消息、状态迁移、重试次数、终态。
- 外部适配器：本地测试服务器验证序列化与状态映射；覆盖超时、非 OK、畸形、部分响应、取消；普通 PR 测试不得要求外部凭据。
- 有状态组件：故障注入让第 k 步失败并断言无部分状态且按声明策略 fail-open/closed 可观测；进程内用显式同步构造 close-vs-use、use-after-close、double-close 交错，仅在 scratch 目标上跑。
- 前端组合：全组合统一一个单测运行器、一个组件层、一个 E2E 框架；每应用至少一条黄金路径；客户端契约测成功/领域错误/传输错误分类、401 刷新重试、请求 ID 透传；PR 门禁顺序 install→类型检查→lint→单测+组件→build。
- CI 放置：集成测试显式标记（tag/env/job），与快速单测分离；有本地栈先记录启动与健康检查命令。
- 硬性门禁：
  1. 外部契约兼容声明无真实样本即未验证。
  2. 出站格无对方接受证据即 unexercised。
  3. 原始样本不进仓库、不进正常测试路径。
  4. 只打印/只冒烟的契约与性能测试不算门禁证据。

## 3. E2E 与真实流程
- 只对关键用户旅程、权限敏感流、跨服务状态一致、浏览器特有交互、最高风险变更的发布冒烟写 E2E；先更新场景矩阵，确定性排列下推到低层。
- 浏览器规则：稳定选择器/可访问性角色；每次动作后重读可见状态；等待显式条件而非固定 sleep；不同角色隔离上下文；捕获控制台错误、失败请求、截图/trace；网络拦截只控非确定性或断言 payload，不能 mock 掉要证明的契约；CI 失败必须留 trace 产物（retries=0 时用 retain-on-failure）。
- 运行时巡检只作有界的验收/发布冒烟证据：查死控件、错链接、可绕过校验、刷新不持久、双提交；交互后再看控制台与网络面板（CORS/混合内容/CSP/4xx5xx）并先分类再定缺陷；看累计布局偏移与请求模式异味；登出态与各角色边界只在 staging/合成租户/只读路径验证，破坏性动作只查护栏不执行。
- 巡检是"记录并路由"，不是原地修：产品代码只读，先关闭证据再另起诊断阶段。
- 后端真实流：断言响应信封、规范错误码、trace/log id、持久化状态、发出事件、依赖结果；隔离租户与 teardown；幂等/重试/补偿可见。
- 被测对象是 agent/自动化自述时→独立重观察持久效果（重读文件、查权威状态、断言未触碰文件字节相同）；自写成功记录与转录关键词匹配不算证据；不安全可重跑的命令不重跑；资源自建自清，外部资源打 run id+TTL 由进程外清理器兜底。
- 交付物是构建/安装产物时→至少一条冒烟从发布入口进入（构建产物、真实加载器、已安装命令），只 mock 外部服务，缺配置须非零退出。
- 范围控制：少而稳，一条 happy path 加高风险负路径；无断言的点击流不是 E2E；页面加载/URL 变化/toast 等弱信号不证明业务结果，要锚定 API 字段、持久记录、余额/计数增量、可解引用的产物；断言强度须匹配用例标题所声称。
- E2E 失败视为真实信号，保留 trace/截图/网络/环境证据走缺陷诊断，不得换成更薄的 mock 测试。
- 硬性门禁：
  1. 无断言或仅弱信号的 E2E 不算证据。
  2. 自述不算证据，必须独立重观察世界。
  3. 发布产物至少一条从真实入口进入的冒烟。
  4. 巡检不改产品代码。

## 4. 场景测试
- 场景测试是覆盖模型不是运行器：先定义场景、识别风险，再把证明放到能断言的最低层。
- 改变行为的交付先从需求/验收源出发建闭合表：稳定条目 ID、in/out/deferred 决策、实现面、场景与层、新鲜证据、状态；每个 in-scope 行都要新鲜证据；gap/blocked/unknown 阻塞完整判定，out/deferred 只有产品或人做过决定才有效。
- 再建紧凑风险矩阵（场景/风险/层/数据准备/断言/证据）：主成功路径、权限路径、空/部分数据、失败/重试、边界体量、回归；覆盖不同风险而非全排列。
- 发布/控制面系统另用专门矩阵：审批门、部署进度流、注册与健康、实时通知、游标迁移、生成客户端/代理、运维控制台；密集图表工作台也有专门矩阵（图表/表格切换、大类目、基准线、阈值、对比模式、导出与清理、跨端指标一致、跨层作用域）。
- 分层映射：单测放逻辑/校验/状态机/映射；契约放形状/鉴权信封/幂等/分页/兼容；集成放事务/缓存/队列/存储/迁移/worker；组件放渲染态/表单/焦点/可访问性；E2E 只放跨边界关键流、会话、路由、上传下载、权限可见动作、发布冒烟；探索性手测记为 bug 或自动化候选。
- 高风险工作流必须覆盖触发的失败类：重复提交/回调/消息/重启、权限服务不确定、跨租户错配、部分资金/配额副作用、AI 供应商失败、刷新/离线后终态不清、缺 trace/支持标识；测量类交付还要防"缺失读作通过、重试改分母、后次覆盖先失败"。
- 复合流水线仅在行为/契约/组合/回退/基线敏感变更时要求模块/链/产品三层验收，纯内部重构不强制。
- 场景选择：一主成功、一高风险负路径、一权限、一恢复、一边界体量、每个近期修复一条回归；组合用 pairwise 或代表值。
- 断言与风险匹配：用户可见测结果/下一步/焦点/文案；API 测状态码/错误码/体/幂等/持久态/事件/trace id；worker 测终态/重试数/死信/产物/数据质量；发布测目标环境冒烟并记录跳过依赖。截图/视频/日志只有配断言才算证据。
- 审计既有覆盖：从命令面与 CI 出发反查文件；保留本地标签语义；回放/压测/影子/演练/live 调试标为诊断工具，无 owner/环境/断言前不当发布门禁。
- 反模式：无断言长脚本、E2E 复刻所有单测分支、只测 happy path、mock 理想响应当真、一场景混多风险、fixture 变生产数据、把依赖/生成/归档测试算作覆盖。
- 硬性门禁：
  1. 每个 in-scope 需求点必须有新鲜证据。
  2. 高风险流必须覆盖触发的失败类。
  3. 证据必须配断言。
  4. 诊断性测试无 owner/断言不作门禁。

## 5. 数据与工作流测试
- 批处理/ETL/流式/定时/回填/回放/流水线→证明：幂等重跑无重复副作用；迟到/乱序/缺失/重复事件按契约处理；窗口/分区/聚合/分页在空窗口、单条、边界、截断、水位、页边界正确；schema 新增/删除/改名/加宽/可空前后兼容；回填回放不污染下游；checkpoint/offset/游标中断后不丢不重。
- 数据质量断言：行数、键唯一、引用完整、空值/范围、对账总额、输出不变量；断言输出 schema 与语义而非"任务退出 0"或"文件已生成"；报表/导出解析后断言关键字段而非比对大 blob。
- 策略：转换规则用小型类型化记录做纯单测；源/汇契约、分区、存储布局、游标持久化、事务边界用集成；E2E 只留一条关键流水线加最高风险恢复路径；定时/窗口任务用固定时钟与场景规模 fixture。
- 禁止：exit 0 当正确、无注入时钟的墙钟窗口、场景断言够用时的全量黄金文件、无命名空间/清理的共享可变 staging 数据。
- 硬性门禁：
  1. 重跑必须幂等且无双重副作用。
  2. "任务跑完"不是正确性证据。
  3. 窗口逻辑必须注入时钟。
  4. checkpoint 恢复不丢不重必须有测试。

## 6. 测试数据与确定性
- 数据用命名工厂/builder，默认有效按场景覆盖；从意图（"过期 token""超限"）派生而非生产标识；必须生产形状时结构化脱敏（换标识、去 PII/密钥、保形与边界分布）；每场景一份最小 fixture，不养大一统 fixture；只提交安全、可读、断言需要的数据。
- 确定性控制项须可注入/固定/归一：时钟、随机种子、ID 生成器（或只断言形状）、顺序（非契约则排序或集合比较）、locale/时区/币种/格式、并发（同步原语代替 sleep）、网络/DNS/文件系统默认隔离。
- 生成型完整性清单（sha256 列表、锁文件式排序产物）用 regenerate-and-diff 校验时，排序必须字节稳定不受 locale 影响（固定 C 排序与字段序），否则跨机器假漂移。
- 属性测试用于解析器/序列化/编码/归一化/数学/往返不变量；fuzz 用于不可信输入边界；固定或记录种子，失败样例固化为命名回归 fixture；属性测试补充而非替代高风险命名场景。
- 何时上属性测试：有代数不变量（往返、幂等、交换、结合、保序）、输入空间大且历史反复漏边界、高风险函数；直线业务逻辑且命名示例已覆盖可跳过；但鉴权/计费/配额/解析器/编码器等高风险域默认要写，"示例已覆盖"只是自查提示。
- 禁止：未固定时区/locale 的断言；只在首次/单时区/串行通过的测试；不归一的非确定快照；原始生产 dump、密钥、私人数据。
- 硬性门禁：
  1. 时钟/随机/ID/顺序/locale 全部固定或归一。
  2. 仓库里无生产 dump/密钥/PII。
  3. 高风险域（鉴权/计费/解析器）默认配属性测试。
  4. 属性测试失败样例必须固化为回归 fixture。

## 7. 测试拓扑与命令
- 陌生仓库先按顺序发现：项目/agent 指南→构建与测试元数据→自动化包装脚本→CI 配置；有文档化包装器优先用，它常设置 env、代码生成、端口、覆盖率、超时、并行、fixture 路径。
- 默认快速目标必须密闭：主动 unset 真实凭据类环境变量（只针对真实凭据，不误杀包管理/CI/假 token）；需要凭据的测试显式标记进独立 live 门；HOME/状态目录重定向到临时最小合成目录（保留 git 身份、CA、缓存等必需配置）；运行级固定 TZ/LANG，但时区/locale 可见行为另加非 UTC/DST/非默认 locale 用例；并行度固定或按测隔离，不同 worker 数结果不同先查跨测试依赖。
- 密闭两层兜底：包装脚本对齐 CI（CI 为真源）并覆盖 import/初始化期读 env；always-on 测试钩子重施同样中和覆盖 setup 之后；两者都要。无包装器时把默认目标做密闭是测试工作的一部分。
- 盘点时排除依赖目录、构建产物、虚拟环境、vendored、生成客户端、归档 worktree；发现的测试文件在弄清"哪条命令跑、是否在 CI、是否需活基础设施、断言什么"前不算覆盖。
- 布局沿用仓库既有约定；新建时按 unit/contract/integration/e2e/scenarios/architecture/fixtures 分目录，不另起平行体系。
- 命令分层：快速默认（格式/编译/lint/代码生成干净/单测）→聚焦验证（改动包+直接相关契约/集成）→可选集成（标记门控）→场景/验收门→E2E/发布冒烟→长门（兼容矩阵/迁移演练/负载回放/视觉回归）。
- 保留既有标记划分；昂贵与计费测试（付费推理、按次 API、真实支付、云沙箱/设备农场）单独 lane、默认 PR 不跑、需命名预算 owner 与授权账号；支付默认沙箱模式，真钱 canary 需单独审批、硬上限与退款清理；通用 e2e 标签下悄悄创建付费资源是 lane 分类缺陷。
- 运行器：Python 异步模式 strict/auto 是有意决策，混用异步库时留 strict，切 auto 前先审计；每个技术栈组合级只选一个主运行器，混跑器共享工具包必须在每个消费方运行器下各跑一套或迁移到单一运行器。
- 报告证据格式：命令、范围、结果、跳过/不可用套件、残余风险，表格呈现。
- 硬性门禁：
  1. 默认快速目标必须密闭且与 CI 对齐。
  2. 计费类测试必须独立 lane 且有预算 owner。
  3. 未知运行命令与 CI 归属的测试文件不算覆盖。
  4. 验证报告必须含命令/范围/结果/跳过/残余风险。

## 8. 闭合契约 oracle 设计
- 断言"允许集"而非"禁止集"：denylist 对可变参数、等号拼接、别名、未来拼写开放，会假绿；检查解析结果时必须连同产生它的输入/argv 一起断言。
- 允许集动态或尚未固化→记为已接受/延期风险，先断言最强稳定不变量，等契约闭合再补。
- 文档化的 allow/deny 条目本身就是契约时，字面断言保留。
- oracle 报告必须逐维枚举已穿越的维度：形状、来源（哪些输入受攻击者/上游控制）、基数（零/一/重复）、语义（像的不等于是）、顺序（消费者顺序敏感时）；同一维度堆更多值对未穿越维度无益，矩阵可以穷尽仍盲。
- 每条违规行旁边永久保留良性近似（near-miss）行：加固只会往召回方向漂，缺少"必须仍接受"的记录会让下次收紧误杀合法流量并看似更安全。
- 两个伴随缺口（未穿越维度、未钉住精度）都在绿色方向静默失败，运行本身不会提示。
- 硬性门禁：
  1. 闭合边界必须正向断言允许集。
  2. oracle 报告逐维枚举五个维度。
  3. 违规行必须配良性近似行。
  4. 未闭合契约需记为已接受风险而非当作通过。

## 9. 强制机制验证
- 任何守卫/闸门声称完成前必须有行为矩阵，且只在 scratch/合成目标上跑。
- 矩阵四组：阻断集（每个外部可观察的拒绝条件一例，不只最容易的）、放行集（合法操作不被误伤）、绕过集（环境差异开出的路径，每个吞异常后落到"允许"的 catch 都是 fail-open，改为拒绝、可见降级或证明确实在范围外）、规范化/读取边界（目标路径与 cwd、尚不存在目录、原始路径与规范化路径不同如符号链接根、守卫读取的 VCS 状态如链接 worktree/游离 ref）。
- 无法安全执行的用例记为"安全不可得"缺口并写残余风险，不得静默跳过。
- 移植或镜像既有守卫时，文档化契约是规格、原实现是对照输入：逐条件 diff，每处差异标"有意分歧"或"关闭旧 bug"，绝不静默继承绕过，两边跑同一矩阵；靠读代码得出的"等价"只算假设级。
- 硬性门禁：
  1. 无行为矩阵不得声称完成。
  2. 吞异常即放行的路径必须改为 deny 或可见降级。
  3. 只在 scratch/合成目标上执行。
  4. 移植守卫必须逐条件 diff 并双跑矩阵。

# 测试手册·第二部分

## 一、测试代码写法

- 每个测试固定 Arrange/Act/Assert 三段，空行分隔；出现第二组 AAA 就拆成两个测试。
- 测试名必须读出「被测单元 + 场景 + 期望」，`test_export_1`、`test_happy_path` 一律打回重命名；名太长说明测试范围过宽，拆单元而不是缩名。
- 断言结果（返回值/状态/事件），不断言「调用没抛错」。
- 测试体内不得有决定断言是否执行的 if/else/loop；表驱动的 case 迭代不算。
- 依赖外部文件/数据必须在测试内显式声明，不留「神秘来客」。
- 快照式断言（注册表项存在、枚举计数、版本号字面量）一律改成关系不变式（每项都有换算因子、迁移抵达当前常量）；字面量只在能追溯到文档化契约或历史缺陷、且测试名点出该契约时才保留。
- 单元测超 100ms、整套超 30s 触警；integration/E2E/benchmark 用 marker 或独立 runner 清单隔出，不混进单元预算。
- 一次 review 抓到 ≥3 处同类异味即登记技术债，不只口头指出。
- 复杂对象构造先沿用仓内既有 fixture 约定；无约定时场景少于 10 且叫法稳定用 Object Mother，字段多组合频繁用 Builder；Builder 必须有合理默认值且不含业务逻辑。
- 默认状态验证；只在跨边界副作用（外部 IO、事件、metric、审计日志）用 mock 做行为验证，且断言「以正确参数调了一次」而非「调了某 helper」。
- 替身只放在昂贵、非确定、不可逆、需特权或不可用的边界；边界内其余下游用真实现，跑在测试自有的隔离资源上。
- 给正式组件手搓替身只证明桥接搬了字节，不证明组件行为；集成测试用脚本化边界替身 + 真执行器。
- 一个测试只用一种验证风格。
- 覆盖率是 floor 不是 goal：CI 设仓库 line 下限（按现状起步再棘轮），关键路径模块单独 ratchet（如 line ≥90%、branch ≥80%）；不用 100% 作 KPI，不拿全库均值卡单个 PR。
- 清理类 PR 允许覆盖率下降，但必须附「删了哪个测试 / 保留了哪个场景 / 替代测试 / 断言等价说明 / 证据」五元组，缺行视为场景失守。
- 覆盖门失败要输出可点击的 `path:line:col`；未覆盖行先当删除候选再当补测候选。
- 每个测试任意子集任意顺序结果一致；串行豁免必须四字段齐全：marker + reason + owner + review_at，裸标 serial 不接受；Go 里缺 `t.Parallel()` 不算 serial。
- 全局可变状态每测前 reset；reset 易漏或框架有进程级残留时升级到每测独立进程（spawn）+ 每测超时，但被测对象本身是进程生命周期/连接复用时不要上。
- 共享 DB/文件用独立 schema、事务回滚、临时目录；用随机顺序运行暴露顺序依赖；不用 sleep 解竞态。
- 时钟注入并在确定性测试里冻结；真实时间只允许出现在显式标记的 benchmark/deadline/签名窗口/replay 测试里，且有上界。
- 相同 setup、相同断言形状、只换输入时用参数化/表驱动；每行必有 name，期望值写字面量不写计算；3–20 行适中，超 20 考虑拆表或属性测试。
- 跨栈移植测试要移植对抗输入的语义类别（大小写混写 header、畸形编码、伪造 trusted 字段、边界值），经目标栈真实入口注入；逐条对账输入 fixture，差异要么记 intentional-divergence 要么算覆盖流失。
- 对抗 fixture 用结构合法、能过真实校验路径的合成凭据打 scratch 目标；无法安全构造记 `safe-unavailable` + 残余风险；权威是文档化契约不是源栈行为，源栈 bug 记 `legacy-bug-closed`。
- 每个文档化 ingress 边界（公网网关与内部 trusted 调用方）各跑一遍对抗用例。
- 行为纠正类变更必然打红钉住旧行为的旧断言，逐层（unit/contract/integration/E2E/golden）找出并同批改写成新契约。
- 交付前逐行走查：断言的是结果、名字读出行为、无条件分支、重复构造已收进 builder、多组输入已参数化。

硬性门禁：
1. 测试名读不出「单元+场景+期望」→ reject。
2. 串行/顺序依赖测试缺 marker/reason/owner/review_at 任一字段 → reject。
3. 清理类 PR 覆盖率下降且无五元组保留证明 → 阻挡。
4. 快照式断言（计数/清单/版本字面量）无契约锚点 → 改为不变式后才能合。

## 二、CI、fixture 与 flake 控制

- CI 分层：快 PR 门（格式/编译/lint/重复与死代码/聚焦单测/codegen clean）→ 集成门（DB/Redis/MQ 容器）→ 场景门（小而可诊断）→ E2E/发布门 → 可选长门（回放/负载/兼容矩阵/迁移演练）；本地验证用与 CI 相同的命令包装器，重复检测门显式配最小 token 下限、排除测试代码、有理由的重复用行内标记围住。
- 派生的已提交产物在 pre-commit 校验新鲜度，形式是「拒绝并打印重生成命令」，不自动 stage；测试车道保留提交树新鲜度断言作为最终门。
- 冻结回归集按成本与副作用分层：免费无副作用的确定性用例进阻塞门；需要真实基础设施、模型调用、付费资源或会改外部状态的用例即使很快也只进发布/预放量门，且带 marker、owner、timeout。
- 对已「完成」的代码主动跑对抗扫描：错误映射边界、并发保护绕过、double-release/double-close；每个确认的缺口先落成失败测试。
- 判定只看故障来源：证据基础设施出错 = `infra-error`（不是 pass、不是业务 fail、不是静默 skip）；被测系统出错或断言为假 = `fail`；前置条件在任何尝试前就缺 = `blocked`；来源不明靠调查，不靠挑好看的结论；`infra-error` 与 `blocked` 同样计入未就绪。
- 外部资产 fixture 只读本地缓存，manifest 提交并在套件前校验 hash，缺失或变更映射为相关用例的 `infra-error`，绝不运行时下载。
- 外部 provider 的恢复路径按层证明：协议级故障服务器（脚本化传输/协议/语义故障，每个行为绑定到目标 attempt，未消费或乱序即失败，fixture 本身不含重试策略）→ 录制回放（只从合成账号录，schema 白名单 + 脱敏 + 秘密扫描，无法录的错误用显式 override 条目）→ 带凭据 live 只证明接线。
- 去掉 sleep 改显式条件；时间相关断言的 oracle 应是「证明不变量的状态」（进程仍活、记录未写、锁仍持有），而非「N 秒内完成」；fixture 寿命推远但绝不无界。
- 套件自己回收所启动的一切：trap 退出与中断信号、按运行私有的路径/进程组识别、发信号前再验所有权、退出时断言无残留进程并检查进程状态而非仅存活。
- flaky 按缺陷跟踪，重跑只是分诊手段；隔离只在缺陷有 owner 时使用并记录原因、复现证据、到期日；多子句断言每个子句要有独立诊断输出。
- 有界保护（超时/重试上限/熔断/清理）的测试要钉住它「约束了什么」：超时类断言工作确实停止，重试类断言次数，熔断类断言 open/reject/probe；测试自身另配独立 watchdog；保护路径至少有一个真正进入它的用例。
- 覆盖阈值按文件而非仓库均值；平台条件豁免与对应 skip 用同一探针推导，探针出错与能力缺失要区分，声明该能力的车道把「不可用」当失败。
- 并行覆盖分片合并后再算阈值；每个分片与运行 id 绑定，缺失/陈旧/重复分片使运行失败。
- 提交前选最窄的、会因本次回归而失败的证据：模块行为→聚焦测试；可见输出→golden/示例场景；文档→文档门；清单/构建配置→构建 + 产物 smoke；早先的绿只在树与依赖环境未变且有记录时可复用。
- 验证报告写明命令、范围、结果、skip 情况、残余风险；证明可选集成的套件要断言最小执行数并对意外 skip 失败；env-gated live 测试至少有一条车道真实执行，用合成/测试范围凭据，只在受信任 ref 与 runner 上跑，fork 流水线不得拿到秘密。
- 测量型 harness：缺失值旁边带编码原因（确认不存在 / 请求了但不可用 / 未尝试），按对照臂分别报告计划/额外尝试/被阻塞的数量，保留最早的决定性结果并记录后续重试原因。
- 条件 skip × 任务选择：期望文件清单来自任务自身的选择 manifest，每个期望文件必须收集并执行 >0 个测试；可选依赖缺失在提供该依赖的任务里是硬失败。

硬性门禁：
1. 默认车道出现付费/改外部状态的用例 → 移出，不得合入。
2. 报告里排除 `infra-error` 用例来凑干净总数 → 假绿，打回。
3. 证明可选集成的套件整套 skip 却报绿 → 视为失败。
4. 过期的 flake 隔离（无 owner 或超 review 日期）→ 阻塞主门。

## 三、杀伤性变异走查

- 走查按测试产物里「命名的属性」逐条驱动，不按改动的断言驱动；改名或加一句 docstring 也是新主张，也欠一次变异。
- 变异前把目标文件复制到仓外临时目录，复制失败即退出；恢复用同样的 fail-fast 复制回来；只有全部恢复成功后才删临时目录。
- 校验备份根确实在工作树之外（临时目录可能被环境变量指回仓内），用规范路径比对而非假设。
- 不用 git stash/commit 当草稿区：stash 跳过未跟踪的新测试，`add -A` 会扫进凭据，提交产生可发布对象。
- 备份配方只覆盖原地内容变异（改函数体、翻常量、删守卫）；符号链接目标、改变文件类型、路径穿出仓库、不能独占持有的文件，一律改用一次性 checkout。
- 变异只打隔离依赖；禁用授权检查/幂等守卫/删除保护后绝不能对共享或真实依赖跑；做不到就把该属性记 `unverified`。
- 破坏性/不可逆产物的探针要编码进套件，逐个受保护谓词重建 mutant，要求套件「因正确原因」失败：mutant 仍能解析/构建、fixture 仍能建立、失败可归因到指名的受保护断言。
- 归因用差分而非子串匹配：拥有断言在未变异对照跑 PASS、在 mutant 下 FAIL，且没有非拥有断言在 mutant 下失败；声明的 owner 标识缺失时 fail closed。
- 探针要断言注入确实落地（mutant 与原文不同），并有递归守卫防止子运行再跑探针。
- 钉住的契约/文档类产物额外覆盖：段落搬家仍能匹配、入口到引用体的路由仍可解析、mutant 在临时副本变红而实时树保持绿、pin 清单由解析 fixture 得出而非手工维护。
- 一次性变异只证明作者当时看过；要让 CI 能重复检查，探针必须常驻套件。
- 编码/解码往返用真实解码器是合法不变式；但反向期望若与正向出自同一来源，两者同漂，需独立推导的 oracle。

硬性门禁：
1. 变异后未恢复或工作树 diff 不干净 → 不得提交。
2. 变异打到共享/生产依赖 → 禁止，只能记 `unverified`。
3. 探针把「非零退出」当命中而未做差分归因 → 无效证据。
4. 命名属性未逐条对应一次杀伤性变异 → 走查不算完成。

## 四、变异备份配方的执行规范

- 备份、恢复的每一步都带 `|| exit`，子 shell 内 `cd` 失败必须退出，否则 fixture 写进仓库根目录。
- 用 `cp -a` 保留 mode 与 mtime；同名文件在不同目录必须按相对路径分别落盘避免碰撞；路径含空格、括号、方括号要全程加引号并用 `--` 终止选项。
- 备份根位置检查用当前目录的物理路径比对，不依赖 git 是否存在；git 缺失应报 SKIP 而非算失败。
- 缺源文件时备份必须失败并可在变异前检测；备份丢失时恢复必须失败并可检测，清理以此为闸。
- 恢复失败要保留备份目录；只有成功路径才删除。
- 验证 git 状态、HEAD、对象库文件清单在整个流程前后完全一致。
- 结果计数解析 stdout 标记，不用子 shell 变量或临时计数目录；断言总数钉死为固定值，加用例时手动上调；总数不符即失败，部分执行不算通过。
- 探测 stat 方言要显式判断 GNU/BSD，不能靠 `||` 回退（GNU 下 `-f` 会成功返回无关输出）。
- 用替换父目录为普通文件制造 ENOTDIR 来注入恢复失败，不用只读权限（root 下会绕过）。

硬性门禁：
1. 断言实际数量 ≠ 预期数量 → 失败退出。
2. 任一 FAIL → 非零退出。
3. 备份根落在工作树内 → 拒绝备份。
4. 恢复未全部成功 → 禁止删除备份。

## 五、架构适应度函数

- 把架构不变量写成每次构建都跑的自动化检查：无循环依赖、分层不越界、DB/HTTP 出口唯一、性能预算、复杂度上限、无硬编码 secret、接口不兼容变更。
- 优先做 triggered + static + automated 的类型；manual 只在自动化不可行时保留。
- 每个适应度函数必须有 owning 决策记录（ADR 或同等 reason）、名字与存在理由；ADR 里承诺「保持 X」就必须有对应函数。
- Fail loud：CI 红而非 warning，本地 pre-commit 同样跑。
- 起步顺序：linter 规则 → 静态依赖图 → 现成工具的不变量模式（秘密扫描、破坏性变更检测）→ 性能预算（最后，需稳定负载环境）。
- 规范落成健康度检查前先分类：Deterministic（脚本/lint/测试）、Agent review（有界 prompt + 证据包）、Manual（人工证据 + owner + 到期）、Not automatable yet（记缺口 + 计划）。
- 健康度报告字段：规则 id、来源、severity、检查类型、命令或 prompt、证据、结果、owner、CI 行为；结果只允许 pass/fail/blocked/inconclusive/not_applicable。
- CI 只卡 blocker 或已声明卡关的规则；warning 进报告并要求责任人，不伪装通过。
- 脚本负责事实，agent 负责判断；任何检查缺具体证据不得写 pass；agent review 超时、范围不足或泛泛结论一律 `inconclusive`。
- 字段存在 ≠ 链路正确：grep 只能证明日志/trace 字段存在，跨 HTTP/RPC/MQ/worker 的传播要集成测试、E2E 或运行时观测才能 pass。
- grep 不够时上 AST，优先标准库 AST；自写检查器只对窄的高价值枚举不变量做，且配 test harness（正例命中、反例不误报、坏 scope 报 inconclusive）；需要完整类型/数据流分析的保持 blocked 不硬 ship 半成品。
- 后端可机判示例：边界层用返回值伪造错误（`{"success": False}`、`(data, err)` 元组）；非 main/init 函数里自造 root context 丢掉 cancel/deadline/trace。
- 检查器退出码约定：1 = 命中，2 = scope 无效/语法错（inconclusive，绝不报 clean），0 = 未发现枚举形态（≠ 完全合规）。
- 测试异味的可判定子集（条件逻辑、sleep、无断言）优先用生态 lint 规则，没有规则的格子记 agent review，不自写 parser。

硬性门禁：
1. 无 owning 决策记录的适应度函数 → 不得加入/可被随意删除，先补记录。
2. 缺具体证据的检查写成 pass → 打回。
3. 自写检查器无 test harness → 不得上 CI。
4. 声明为 blocker 的规则失败 → CI 必须红。

## 六、非功能场景（后端与数据）

- 性能/负载/延迟/吞吐预算：门放在 CI，测量方法按基准工具走；预算值先定再测。
- 安全边界：authn/authz、重放、注入、租户隔离、权限绕过必须有断言式负路径测试，不能只有正路径。
- 高风险韧性：金钱/配额/记账、权限不确定、租户数据隔离、重复写、重试/刷新/离线后的用户终态、事故可追溯性必须有场景测试或演练。
- 重试与降级：先分类错误再重试；有界退避加抖动；处理 retry-after；等待中可取消；跨 SDK/网关/队列/任务/用户各层的重试放大要有控制；配额耗尽、权限拒绝、畸形请求、上下文溢出为零重试终态；用户中止为终态。
- 客户端重建只在完整元组（主体、租户、凭据代际、路由、模型参数、策略版本、会话代际）仍匹配时复用，任何一项漂移即取消并全量重建重授权。
- fail-open 只允许非关键的咨询类策略拉取，且缓存匹配完整元组、有最大陈旧时长与单调撤销纪元；安全/权益/隐私/权限门 fail-closed，陈旧 allow 不得覆盖更新的 deny/撤销/登出。
- 用量与成本按 request id、provider request id、幂等键/用量事件 id、attempt id 在重试、流重连、延迟完成等所有终态路径去重；成本未知打标记；fallback 换路由算新的授权尝试单独计费。
- 持久化配置迁移：覆盖源缺失、已迁移、显式偏好、旧默认、作用域值不得提升、列表去重合并、deny 与缩窄优先、重复运行幂等、部分写失败、回滚版本可读、旧键保留/删除时机、迁移失败时的启动行为。
- 远程策略：校验和/ETag 命中、畸形 schema 拒绝、旧策略重放拒绝、低于已接受纪元的回滚拒绝、last-known-good 只在元组匹配且未超陈旧规则时使用、空响应清缓存、后台轮询幂等、主体/租户/登出漂移即清缓存。
- 令牌刷新是状态机：按过期时间调度、缓冲下限/上限、临近过期立即刷新、主动刷新与鉴权失败恢复互斥、单一路径拥有新凭据与代际、会话/账号漂移后拒绝陈旧完成、传输重建时旧传输关闭且高水位带过去、重试耗尽产生可见降级且不泄露凭据。
- 任务编排与后台 worker：稳定 task id 与父/会话关联；命名空间绑定主体/会话/工作区；并发下的 create/update/delete/claim 与锁竞争；依赖图拒绝环、悬挂、跨命名空间边；终态单调，重复完成与重复通知抑制，终态后的迟到进度/审批/输出拒绝；父取消只级联到自有子进程；孤儿资源清理；恢复时拉取新鲜状态、校验代际与作用域、在途回调不得覆盖已终止状态。
- 外部副作用：task id 绑定 attempt/effect id 或幂等键；prepared/committed/failed/unknown 终态持久化；替换 worker 对 committed/unknown 效果做对账；无「未提交」持久证据不得重执行；unknown 终态可见并可修复。
- 每轮模型循环终态：用户输入在调用前持久化；每个 tool-use id 恰好一个终态结果（含缺失工具、拒绝、校验失败、中途中止、预算停止）；崩溃/恢复后回放不能分叉、重复或丢失；孤儿 tool call 不得进入转录、缓存或下一轮输入。
- 上下文压缩：阈值与预留预算计算、连续失败熔断、丢弃旧轮次时不留下孤立 tool-result、只有授权/隐私/来源标签证据的轮次被丢时 fail-closed、tool-use/tool-result 配对保留、压缩后重新校验授权元组。
- 持久化工具输出产物：超大文本/结构化数据/二进制的替换路径、并发写、标记先于持久写可见、中止后的迟到写、摘要/快照不匹配、清理与保留策略；保留原始大小与截断元数据，未读完不得下结论。
- 诊断输出只含有界原因类、计数、时长；令牌、请求体、端点、会话 id、本地路径、凭据、自由文本错误一律缺席。

硬性门禁：
1. 安全边界改动没有负路径断言测试 → 不得合入。
2. 金钱/配额/重复写类改动只有 happy path → 不得批准。
3. 有外部副作用的任务无幂等键/effect id 绑定与终态持久化 → 打回。
4. 诊断或日志出现凭据、令牌、请求体、本地路径 → 阻塞发布。

## 七、研发测试标准模板

- 标准先写权威与范围：上级 Spec 链接、覆盖的技术面、明确不管的项（探索性检查、仅生产验证、各栈机制细节）。
- 每个变更合并前必产出一种记录：测试层决策表（任何行为/契约/harness/发布风险变更）、测试用例登记（产品可见、契约可见、bug 修复、高风险、流程变更）、自动化测试（可确定性证明的风险）、运行时 smoke/手工证据（需要真机或 live 依赖）、回归条目（已修 bug、事故、确认坏例）。
- 分层策略：单元证纯逻辑/校验/映射/错误翻译；契约证 API/protobuf/envelope/生成客户端兼容；集成证 DB/Redis/队列/存储/迁移/事务/序列化/权限数据形态；E2E 证关键流程与一条重要失败路径；场景是规划层，放到能断言风险的最便宜层，不全推到 E2E。
- 每个仓库有跟踪的 harness：文档化本地包装命令、密闭快测环境（假凭据、临时用户态、固定时区/locale、确定性时钟随机）、fixture builder 与 reset 钩子、CI 与本地同命令、`unit/contract/integration/e2e/slow/live` 明确标记。
- Go 服务最低要求：单元覆盖领域逻辑/校验/幂等键/权限决策/错误分类；契约覆盖 envelope、生成客户端、向后兼容、超时取消语义；集成覆盖 MySQL/Redis/事务/迁移/分布式锁/缓存失效/消息重试/跨服务客户端；API smoke 覆盖关键调用方流程与高风险失败类。
- Python 服务最低要求：单元覆盖领域逻辑/设置解析/依赖适配/幂等决策/资源作用域解析/错误映射；契约覆盖路由、Pydantic/OpenAPI、响应 envelope、兼容敏感字段、规范校验失败；集成覆盖 ORM/迁移/Redis 锁缓存/队列 worker/事务/异步取消；live provider、私网、真实数据集、模型服务、回调投递必须标出快门之外并带 owner、timeout、发布决策。
- CI 门表：快 PR 门每次合并阻塞；契约/集成门在契约、存储、缓存、服务客户端、迁移变更时阻塞；场景门在产品可见与高风险变更时阻塞；E2E/发布门在发布与跨服务变更时阻塞；长门定时或预放量。
- 必需门 fail closed；可选或 live-only 门要写明 owner、触发条件、timeout、环境、所支撑的发布决策。
- 高风险流程实现前先写紧凑风险矩阵，覆盖：重复提交/回调/消息/任务重启，权限服务不确定与跨租户错配，金钱/配额/计费/库存/写终态副作用，部分失败/重试/回滚/超时/取消/终态不明，AI provider 失败或降级，缺 trace id/support id/审计日志。
- 完成报告按层填表：命令或产物、结果、缺层原因、残余风险与 owner；不能只凭命令输出说「测过了」，重要场景要映射到用例或显式 `blocked`/`live-only`/`product gap`/`not applicable` 行。
- 同步规则：产品 Spec 管验收范围与场景优先级，测试标准管分层/harness/CI 门/证据格式，栈标准管框架与命令细节，仓内契约管本地边界；改稳定契约、生成面、流程或 CI 门时同一切片更新所有 owner 文档。

硬性门禁：
1. 变更合并前缺对应测试交付记录 → 不合。
2. 高风险流程无风险矩阵或只有 happy path → 不批准。
3. 必需 CI 门未 fail closed → 视为门不存在。
4. 完成报告缺按层证据表或用「测过了」代替 → 退回补证据。
