# 计费与商业化系统设计手册

来源：一位工程师在视频 AI 产品上做支付/积分/订阅/防刷/成本归因的设计文档、实施计划与线上排障记录。条目格式：什么时候 → 怎么做 → 怎么验证。数值只保留通用规则。

## 1 账本模型

- 设计余额存储时→用两本账：扁平余额表（每用户 available/frozen，Redis 镜像）是唯一扣款权威，分批桶表（每次发放一条，带 expires_at）负责记账与过期口径→排查"能花多少"只看扁平表，桶表只解释来源。
- 消费时同步桶表→按 best-effort 从桶扣减，失败即漂移不阻塞扣款→用"扁平余额 = Σactive 桶剩余"巡检漂移量。
- 每笔计费动作→只走 freeze → consume/refund 一个服务入口，退款分支之后绝不再发 usage 事件→单测断言 refund 路径无 usage 事件。
- 结算实扣与冻结不等时→实扣<冻结退差额，实扣>冻结从可用再扣 shortfall→shortfall 按工具/模型打结构化日志和指标，发现定价与冻结不同步。
- 能在调用前算准价格（按次、按分辨率、按字符、按已知时长）→冻结额 = 结算同一公式，不另做"保守预估"→consume 后无 shortfall、无退差。
- 事前算不准（LLM 输出长度）→动态冻结 = 估算输入 token×输入价 + max_output×输出价，max_output 有硬上限→对比固定冻结，冻结/实扣倍数应接近 1。
- 动态估算失败→静态兜底链：具名冻结行 → default 冻结行 → 代码常量（仅库里无 default 时生效）→调默认冻结改库不改常量。
- 所有外部价格→统一存 USD，唯一换算点 credits = ceil(usd × 每美元积分数)，Redis/Lua 只操作整数 credits→改换算率后所有服务等比缩放的测试。
- 定价表→放数据库，启动 seed 只增量插入缺失 name 不覆盖已有行；子键字典（如按模型的单价）需合并新键→全量对齐要先删表再重启，并写运维说明。
- 模型名匹配→精确名优先再前缀，未命中走默认价常量→审计脚本对比库与文档。
- 写定价配置→按 type 校验必填字段（token 需 input/output，service 需至少一种单价）→避免静默落到默认价或 0。
- 桶过期作废→四步：桶表 CAS → 扣扁平余额（Lua 内含一次性标记）→ 落库 → 记桶账；入队发生在 CAS 之前，队列只存 balance_id→崩溃在任一格都能从队列找回。
- 作废扣减金额→只用 CAS 返回值或 CAS 同步写下的 last_drained_amount，不用扫描快照（全量一遍要数小时，快照已过期）→对比三本账同一 settle_key。
- 作废幂等标记→无 TTL（生产 volatile-* 会淘汰带 TTL 键，被淘汰的标记无法证明"没扣过"），值存 {实扣额, 时间} 而非 "1"→巡检可判"标记在、账本无行"。
- 作废流水→桶交易与账本行都用确定性 _id（expire:{balance_id}），重放即 upsert；不加二级唯一索引（历史脏数据）→重放后行数不变。
- CAS 结果 contended→是重试不是"无事可做"，不能关闭队列行→dead letter 只能由外部指标看见。
- 负余额→手动发放校验 ≥1，扣费 ceil 后至少 1；发放后余额以本次发放额为下限（漂移或作废额>余额时拉回）→下限只在异常路径触发。
- 手动发会员→与续费走同一事件链，不是叠加也不是重置：先作废到期日 ≤ 新周期起点的桶（含赠送/手动桶），再作废其余订阅桶，再发放净变化；未到期赠送桶保留→后台加提示与二次确认，运营补差以发放前后实际余额为准。
- Redis 缺 key 时回填→create-only（EXISTS+HSET 一个脚本），并发者可能已回填并改过→绝不用裸 HSET 覆盖。
- Redis→DB 持久化→带单调序号，读快照时在同一脚本内递增（先 EXISTS 防 HINCRBY 造出只有序号的 hash），旧序号写入被拒→序号不参与任何金额计算。

## 2 计费触发与时机

- 收费原则→有产物才收：免费试用只在工具成功返回给调用方后才 consume；扣点后构造响应失败要退点并释放试用槽→测"扣点后失败"路径的余额与试用槽都复原。
- 一次用户请求含多轮 LLM 与工具→按 turn 延迟结算：请求开始登记冻结，done/abort/断连时统一 settle（无工具/全失败/有成功工具三类）→settled_total 按 reason 与 charged 分布。
- 事件驱动之外→定时清扫器每 N 秒扫 stale turn 强制结算/退款，空轮也刷新 last_success gauge→gauge 落后即告警。
- 冻结 TTL→不能短于长任务时长；轮询型长任务用带外冻结独立 TTL 或完成前续期→"冻结先于结算过期"计量为 uncollected，事后不补扣（产品决策），只修让冻结活到结算。
- frozen>0 但冻结记录丢失→幽灵对账退还并记 source=reconcile→基线为 0，任何一笔都要查记录为何丢。
- 工具级冻结与对话级冻结→独立并存，各自 consume/refund，用不同 reference_type→余额不足时返回错误给模型而非抛 HTTP。
- 余额不足→402 携带本次估算所需 credits；短请求估算冻结为 0 不会触发→复现要用足够大的上下文。
- 前端付费墙→依赖带 code 的错误帧先于终态 done 帧到达；任何缓冲/重排让 done 先到，前端会合成通用错误→测试固定"错误原帧 → done"顺序。
- 订阅取消→周期末生效，权益保留到 period_end；CANCELLED 且 period_end>now 仍是有效会员→权益解析包含此状态。
- 支付渠道"订阅已激活"事件→在 checkout 时就发，不代表付款；激活与发放只挂 invoice.paid→乱序到达测试。
- 首期扣款失败→订阅停在 incomplete/PENDING，不发放权益，超时自动过期→无需额外清理。
- 用户主动 abort→退还未消费冻结，记 terminal_reason；caller 取消不是 provider 失败，不可重试→refund 行 reason_code=request_aborted。
- 同一生成目标连续重试→按目标身份（非工具名）计数上限，observe 先于 enforce→计数在会话状态里，turn 结束重置。

## 3 幂等与一致性

- 收 webhook→按渠道 event_id 验签+去重，命令幂等键绝不当 webhook 身份→重复 event 直接 200。
- webhook 处理中→PROCESSING 原子 claim 写 owner/expires/attempts；有效租约内重复投递返回成功，过期租约可接管；管理员重放必须真正重放持久化 payload→"写完 PROCESSING 后崩溃、同 event 重投只完成一次"。
- 接收方幂等账本 observe→enforce→先建生产索引；enforce 后 FAILED_UNKNOWN 停止自动重放（宁漏发让人补，不可重发）→backlog gauge + 值班时限。
- 发放幂等键→只用稳定字段（payment:{sub}:{period_start}、credit_refresh:{sub_no}:{refresh_month}），不含时间戳；重试时用持久化的原参数不重算→稀疏唯一索引，历史数据不受约束。
- 高风险命令（建单/订阅/升级/优惠）→(user, operation, key) 存 canonical hash 与首次结果；同 key 不同 payload 返 409；处理中租约 + 递增 fencing token，每个渠道副作用前实时读库校验 owner，不缓存成功断言→takeover 后旧执行者无外部副作用。
- 敏感响应（checkout URL/client secret）→独立集合短 TTL，主记录只存引用；过期后按引用重建，重建失败返可重试 503 禁止再次 create→存 hash 不存原始 payload。
- 调渠道 create→用稳定派生 idempotency key；产品/价格 key 绑定带版本的 canonical payload，配置变化生成新 key→list-before-create 不是事务，最终去重靠渠道键语义。
- 多步骤副作用（优惠券→checkout→…）→先持久化固定 target，每步成功再记结果；重试只续跑未完成步骤，不按实时余额重选分支；优惠券失败直接终止不能静默无优惠→断言不会创建无优惠 checkout。
- 跨服务发放→先原子写事实 + delivery_status=pending，再调对端，对端按 invoice_id 去重，成功标 delivered，扫描重投→禁止"已记事实就跳过投递"，否则付款用户永久拿不到额度。
- 桶表写→remaining/frozen/version 乐观锁 CAS，三条不变量（冻结部分不动、有冻结的桶仍 active、无金额变化不写流水）只有一处实现→返回 (changed, drained, frozen, contended)。
- 分布式定时任务→单 leader 锁带 TTL，多 pod 指标用 max 聚合→锁超两倍 TTL 仍被死 pod 持有即异常。
- 依赖 partial unique index 裁决并发→目标数据库（兼容型文档库）可能静默不建；上线前 getIndexes 确认 partialFilterExpression，并手工插两条断言唯一冲突→不支持则退普通 unique，补偿记录另建集合。
- 失败分类→按资金证据分 pre_mutation / mutation_unknown / post_mutation / compensated / compensation_failed，不按异常类型；取消异常落在哪阶段算哪类→只有 unknown/post/compensation_failed 告警。
- 混合版本→未知字段一律忽略不报错；新字段全部可选；旧节点不发新事件但行为一致→兼容矩阵逐格写"必须成立的行为"。

## 4 订阅与权益

- 升级→立即生效，按剩余天数抵扣，旧余额合并进新桶（升级是唯一合并场景）；同一用户只保留一个活跃订阅，优先原地修改渠道订阅而非新建→升级后渠道侧与本地各只有一个 ACTIVE。
- 降级→不支持，退订后重订低档；年付无退款只停下次扣费→接口对降级请求报错。
- 续费→先作废旧余额再发新额度（expire → grant），禁止双活；作废按 (source_type=订阅, source_id) 双重过滤，不误伤购买/赠送桶→crash 在中间用户短暂为 0，靠重试恢复。
- 年付按月发放→定时任务每日跑，按订阅日触发，29/30/31 日在短月取月末；首月跳过（首付已发）；月份标记在发送前原子更新→标记更新后发送失败必须写重试元数据，否则永久丢月。
- 年付 period_end→日历对齐到下个订阅日 + 宽限时长防断粮；宽限带来双活由主动作废解决→两者缺一：只宽限会双活，只作废会断档。
- 年付续费→走渠道 invoice.paid 不走月度 refresh，同样要作废第 12 月余额→分支按 billing_period 与 is_upgrade。
- 订阅日→对齐首次正式扣款日（trial 结束日），否则月度发放早于扣款→与首月守卫一起回归。
- 权益模型→权益 key、套餐权益映射、显式 grant（limit/scope/起止）、用量表（user, key, scope, scope_id 唯一）→解析顺序：显式 grant → 当前订阅 → 付费历史 → 免费套餐 → 用量 → deny。
- grant 与订阅冲突→任一来源允许即允许；配额 grant 只扣对应 grant 不扣订阅→分层 resolver 各自单测。
- 免费一次性权益→终生累计不重置（注销重注、退款、到期都不重置）；曾发生真实商业行为永久解除次数限制，但不授予会员权益→bypass 与会员权益是两把锁。
- "新用户"定义→展示与下单共用最严一套（订阅含手动/迁移 + 已付积分订单）；弃单（渠道字段有值但零实付）不算付费，需实付证据；手动/迁移与实付条件解耦→存量回归只允许"弃单 true→false"翻转。
- 会员试用 grant→不建订阅不碰渠道不计付费历史；要解除免费次数须同次显式授予 bypass→到期自动失效，可撤销。
- 上线权益系统→不回填历史 grant，旧事实 read-through（旧试用表、旧订阅、旧订单）；无事实源的历史手动积分由运维按需重发→老用户不能重获免费试用。
- 权益服务不可用→按类型区分：付费权益 fail-close，试用次数 fail-open 可配置→两开关默认值写进配置示例。
- 白名单→无水印/原片只给付费可信用户或运营明确白名单→白名单是显式 grant 不是代码分支。
- 权益回滚→后台立即取消清空该订阅积分，周期末取消不清（两条成对验收）；退款/拒付不回退兑换事实→测试成对。
- 存量迁移→赠送权益本地发放并标记等级，不创建付费订阅，支付系统只留真实付费记录→迁移完全不经支付服务。

## 5 促销与试用 SKU

- 促销形态→复用正式套餐 + trial_period_days + 一次性 invoice item，plan_id 不变；否决独立短周期套餐、schedule 切换、循环价、setup-only→月付年付共用同一 offer_id。
- 渠道 trialing→本地映射 ACTIVE 让既有权益生效；发放分叉必须靠 applied_offer + billing_reason，不能靠状态或金额比对→币种/税/优惠券会干扰金额。
- 周期字段→已迁到 subscription item，顶层为 null；用 anchor 推算会得到 +1 月（年付再被抬 +1 年）；SDK 对象继承 dict 时 `.items` 属性遮蔽→用下标取值，促销首期只认 trial_end。
- 周期有多个写入点且 webhook 乱序→验收直接断言 checkout.completed 处理后的 period_end，不看额度有效期→两种顺序各跑并重放。
- 首期发放→读 offer.upfront_credits，跳过首付 bonus，过期 = trial_end 无宽限（宽限是年付 refresh 的工程缓冲，不是产品裁定）→转正扣款成功先作废旧额度再发正式额度，验证作废确实命中。
- 终生一次→独立兑换事实表 (user, offer) 唯一（partial on CONSUMED），只在收到钱时写，不可逆，与发放共用 invoice.id 幂等键→订阅状态是可变的，不能用订阅表 partial index 兜。
- 重复单→不发任何额度（发正常套餐额度资损更大），取消订阅，退款走确定性 idempotency key，告警；补偿事实以 invoice 唯一，同 invoice 是赢家续跑不是输家→不做下单预占（会挡住自己犹豫重试）。
- 报价决策→支付系统签发版本化 token（绑 user/offer/plan/period/price/配置版本/过期/schema 版本），中间层与前端只透传；漂移直接拒绝，不静默换价、不自动重报价；旧客户端无 token 一律常规价→中间层禁止用随机 UUID 覆盖 token。
- 资损闸门→一次性价格下单前校验无 recurring；上线前 test 账号跑完一个续费周期确认发票只有一条 recurring 行；多 offer 撞车按 offer_type 显式分派→退款按实付封顶。
- 退款/拒付→先只记录+告警不自动回收，拿到真实比率再决定→促销放大拒付经济性。
- 部署顺序→修既有缺陷（独立 MR）→ 暗置计费能力且 offers 关闭 → 前端接入观察 token 覆盖 → 开启决策 enforcement → 最后配置 offers→回滚先关 offers；pending 投递或补偿未清零时禁止回滚二进制。
- 灰度硬门槛→首期额度过期时间分布全部等于 trial_end 才扩量；资格命中率单独拆维度（否则误杀表现为"转化偏低"无法归因）→出现月量级值立即停放量。
- 托管支付页文案→配置层无法改渠道固定措辞，产品裁定接受；口径反转只剩自渲染一条退路→工期重估。

## 6 支付主体迁移

- 换法律实体→用渠道官方客户+支付方式复制，customer_id 不变，拿 mapping CSV（旧 PM→新 PM）；订阅/发票/价格/优惠券不复制→复制后抽查新账号客户已有支付方式。
- 新账号→脚本先建产品/价格并更新本地映射，再遍历 ACTIVE 订阅重建：billing_cycle_anchor 与 trial_end 都设为旧 period_end、proration none、default_incomplete，旧订阅 cancel_at_period_end→新订阅状态 trialing，旧订阅已标周期末取消。
- 执行→dry-run → 10 → 100 → 1000 → 全量，脚本用 is_migrated 幂等可重跑，先导出集合快照→每批查错误率与两边 Dashboard。
- 切换→先配新 webhook 再换 key 再重启，最后关旧 webhook→建测试订阅确认走新账号。
- 分流→切 key 后新用户直接在新账号；老用户在旧周期到期后由新账号首次扣费→监控两周 invoice.paid/payment_failed。
- 不迁历史→发票/争议/退款留旧账号只读供税务查询，本地历史 ID 保留审计→不删旧账号。
- 边界→PENDING 跳过，PAUSED 单独处理，有 schedule 先 release，优惠价订阅需先建对应价格，无 PM 映射记异常引导重绑卡→时机选在旧订阅刚续费后。
- 回滚→取消新账号已建订阅，恢复旧订阅 cancel_at_period_end=false，恢复集合快照；换 key 后出问题直接换回并重启→积分在本地库不受迁移影响。

## 7 防刷与风控

- 拦截分层→注册/身份 → 业务 token → 会话/沙箱 → 高成本工具 → 导出/下载 → 前端一致性，统一由网关策略层回答"此主体现在能否做此动作"→动作分类（低成本聊天/生成/导出/原片下载/预览）。
- 价值转移点→生成成功拿到原片就已拿走价值，不是导出才算；免费额度足以产出商用素材时把优先级从导出提到生成前→统计用服务端归一化分辨率和输出元数据，不用请求值。
- 拦截点→供应商调用前统一预检，不靠扣费失败或生成后补救→攻击簇用户不触发上游请求。
- 免费额度≠现金余额→gift-only/低信任只能水印预览，无水印原片给付费可信用户；生成路径自身强制水印，不依赖导出水印→带 watermark_status 审计。
- 注册结果四态→allow / challenge_required / low_trust / blocked；low_trust 不发欢迎积分，challenge 的积分 pending_verification 通过后释放→风险画像落库带 decision_id 供后续读取。
- 前端不是安全边界→高成本接口只接受服务端风控后签发的带 risk claims 业务 token，裸 IdP token 只能换 token 或调低风险只读接口；legacy 缺 claims 按 low_trust→页面访问/Referer/UA 只作信号。
- 风险主体→聚合用户/设备/IP/邮箱域/支付状态多身份，快计数 Redis 长期事实 Mongo→换 IP/邮箱/登录态不能重置免费额度。
- 资产访问→前端只拿 asset_id，预览短 TTL 签名，下载走策略授权并写 grant 审计，跨用户拒绝→不再返回永久 URL 的计数应归零。
- observe→enforce→所有长期策略先 observe 记"本会怎样判"，不改业务；每个动作类独立 kill switch；已验证攻击路径不走 observe 直接 100%→canary 期请求成功率、计费事件、上游请求数不变。
- 指标→只用低基数标签（action/decision/mode/primary_reason），明细进审计集合→禁止 user/IP/email 标签。
- 依赖顺序→止血 MR 不等平台底座；观察底座不阻塞止血但硬阻塞统一 enforce；先上后对齐标签→MR 依赖图写清 hard/soft。
- 三方风控服务→只写风险信号不写业务状态，超时/降级/审计必备；不可用时按动作价值 fail-open/closed→低风险只读可开，高成本关或降水印。
- 成本权衡→人工审核只留给高价值且规则判不清的 case；先可解释规则不上 ML；不做 DRM 级保护，短 TTL 签名 + 加密分片够用→避免运营负担失控。
- 应急封控→批量标记攻击簇、冻结剩余赠送额度、历史资产标 review_required，全部可审计可回滚→dry-run 后分批写。

## 8 成本归因与毛利

- 成本库各平台→逐一标注金额类型：平台账单费用（可当折后应付）vs 额度/用量推算（不是账单）；账单≠已付款；折扣只在有折扣账号打一次→推算项标"估算"不进应付。
- 汇率→单价折美元与对账折回必须同一汇率，或直接在账单原币种对账不做往返→往返差会被误判为"反算漏钱"。
- LLM 用量→prompt 是否含 cache 按供应商家族区分（部分含、部分不含），相加会高估数倍；换算放一个共享函数且保持线性（物化依赖 f(a)+f(b)=f(a+b)）→对比月账单科目。
- 定价表→是向用户收费的基准价不是供应商价（可被运营覆盖）；供应商刊例单独维护→credits = 收费×换算率精确成立。
- 内部研发用量→单独科目不进产品对账→之前当"缺口"是误判。
- 流水 tool_name→会随通路改名，统计用前缀或枚举两名→按旧名统计会出现"触发率跌 0"。
- 场景归因→tool_name 为空归对话；不产生供应商成本的工具为 0 是事实→逐工具维护场景映射。
- 复算能力→账本 token_usage 补 resolution/char_count/duration/synth_tokens/discount_ratio→仅凭 tool_name 无法复算账单。
- 毛利→(收费 − 供应商成本)/收费，按 $/credit 分供应商→看板与账本重算数字一致。
- 聚合物化→只读不写库，测试假集合必须按真实管道路径取字段→变异走查假集合本身。
- 重算→累积式存储先清旧值再重跑→否则旧值残留。

## 9 告警与对账

- 恒等式→扁平余额 = Σactive 桶剩余；作废标记实扣额 = 账本 expire 行 = 桶让出额（差值 = clamped，滞留人群常态）；输入 + 缓存读 + 缓存写 = 总输入；credits = ceil(usd×率)→定期巡检。
- 清扫器停摆→last_success gauge 落后阈值或 series 缺失（必须带 absent 分支，懒注册的 gauge 缺失与 0 不可区分）→恢复后有一波补偿性增量属正常。
- 资金不确定→mutation_unknown / post_mutation_error / compensation_failed 任一增量即告警不设阈值；OTel counter 首次出错 increase 看不见，用 unless offset 补→先看 compensation_failed（扣了没退）。
- 幽灵对账、结算未收→基线 0，出现即回归→找记录为何丢或冻结为何先过期。
- 作废死信→重试耗尽后 $setOnInsert 让重入无效，只能靠 backlog{failed} 告警 + replay 脚本；该告警不带 absent；stalled 告警带 absent→影子臂也刷新 liveness 戳。
- 支付回调→FAILED_UNKNOWN 与 PROCESSING 超时各一条告警，附值班时限；处置先按幂等键查桶是否已存在：存在标 COMPLETED 不补发，不存在让上游重发→不确定先不动。
- 延迟结算→Redis 错误率（P1）、清扫死机（P1）、settle 失败率、孤儿冻结相对基线倍数、in-flight 堆积、turn 生命周期接近超时→先 ticket 观察一周再升 page。
- 促销资金链→stale PROCESSING、投递挂起、补偿积压、决策拒绝率按 reason 分流、首期额度过期异常（立即停放量）、退款拒付率→每条写 owner 与处置。
- 取证手柄→trace_id、billing_correlation_key、freeze_id、run_id、settle_key 三本账同串→账本行索引这些字段。
- 处置原则→先确认钱的状态再决定补偿，不凭异常文本猜→有 freeze 无 consume 等清扫退还；有 consume 查余额同步。
- 巡检配置→断言 Redis maxmemory-policy 仍是 volatile-*（测试钉得住代码钉不住配置）→变 allkeys-* 前提失效。
- 积压指标→不按环境泳道过滤，数整个集合→切分会让死信从唯一告警里消失。
- 阈值→没有生产数据前不猜，先看趋势→积压在一遍完整扫描内增长正常。

## 10 上线 runbook 模板

- 前置清单→阻塞缺陷已修或风险 owner 书面接受；产品决策（放量节奏/边界策略）已记录；队列为空；告警已加载到生产；面板已导入；影子期最近一轮健康且量级稳定；依赖配置（Redis 策略）确认；补偿脚本在生产环境 dry-run 可跑→全部打勾才能开。
- 放量粒度→若没有按维度过滤开关，唯一切段是时间窗 [T0,T1]，回滚按同一窗口补偿→先记 T0（UTC 到秒）。
- 开关→patch 配置并回读；配置不改变已运行进程，必须滚动重启且镜像固定为现网 digest→只让配置生效。
- 首轮→看 accounting 行：作废数/扣减数/clamped/duplicate/contended/失败；clamped 高是常态，contended 应接近 0，失败应为 0→首段只跑一遍就关，抽样核对两本账再决定长开。
- 停线条件→死信或停摆告警、失败>0、contended 连续三轮非 0、作废数与影子期同批次对不上、"标记在账本无行"→任一命中改回 false。
- 关开关→只停新增作废，一分钱不还，队列行不自动收尾；真正回滚是按段补偿脚本，补偿不删原流水另写反向行；执行前导出原行存档（确定性 _id 会被再次作废覆盖）→补偿是加钱写操作需明确授权。
- 跨仓发布顺序→消费端先上幂等/兼容，生产端后上变更；每个 MR 独立可回滚并写清回滚后处于哪种旧状态→混合版本矩阵逐格验证。
- 混合版本→老节点不发新事件、新字段可选、行为一致；映射外部 reason 到策略 reason 需显式文档→客户端 i18n key 不是策略 reason。
- 灰度观察→合入后各观察一天日志：预期动作有日志、幂等跳过频次低；人工构造失败验证重试恢复→重试后只有一条流水。
- 收尾→存量清完后流转工作项、更新交接文档、应用告警规则、导入看板、发布 Launch Notice→剩余异常逐条归类为"设计内"。

## 11 典型 bug 清单

- 冻结额是实扣十几倍锁死余额→固定人工冻结值→按请求动态估算，静态配置降为兜底。
- 年付月度发放出现双活余额→宽限期让旧桶 expires_at 超过清理 cutoff→发放前按 (订阅类型, 订阅 id) 主动作废。
- 年付月度发放失败永久丢月→发送前已原子更新月份标记，重试只扫另一事件→失败写含原参数的重试元数据并按事件分支重试。
- 年付周期被算成 +1 月→SDK dict 子类 `.items` 被内建方法遮蔽→下标取值 + 修复前后逐字段回归。
- 弃单用户被判"已付费"失去促销资格且突破免费上限→渠道字段单独成立→需实付证据，手动/迁移解耦。
- 同账号并发两单拿两份首期额度→资格只在下单时校验，支付侧无复核→兑换事实表唯一索引 + 支付侧复核，重复单不发额度。
- 余额为 0 不弹付费墙→错误帧被缓冲，运行时 done 先投影→失败终态由 outbox 按"错误原帧 → done"发布。
- 免费试用失败仍被消耗→扣点后响应构造失败未回滚→成功返回才 consume，失败退点释放槽。
- 免费用户批量拿走无水印原片→生成链路未传水印参数且返回公开 URL→生成路径强制水印、只返 asset_id + 短 TTL 授权。
- LLM 成本高估 3 倍→prompt 与 cache 相加→按供应商家族取有效 prompt。
- 对账覆盖率卡在验收线→单价折美元与折回用两个汇率→同汇率或原币种对账。
- 折扣触发率跌到 0→流水 tool_name 改名→前缀匹配。
- 任务成功但未收费→冻结 TTL 短于任务时长→带外冻结独立 TTL，计量不补扣。
- 冻结退还找不到记录→Redis key 被驱逐/写失败→幽灵对账退还并查驱逐指标。
- 作废死信永远停着、补偿后再次作废覆盖历史行→$setOnInsert 让重入无效、确定性 _id 按"只作废一次"设计→外部告警 + replay/compensate 脚本随开关交付，补偿前导出原行存档。
- 幂等标记消失→带 TTL 的键被 volatile-lru 淘汰→标记无 TTL 并存实扣额。
- 回填余额覆盖并发写、序号计数造出空 hash→裸 HSET、HINCRBY 无 EXISTS 守卫→EXISTS+写入放同一脚本，create-only。
- 手动发会员后用户"原积分没了"→发放先作废到期桶→后台提示+确认，运营按发放后余额补差。
- 升级 checkout 报参数互斥→同时传优惠券与允许输入优惠码→有优惠券时移除后者。
- 单测全绿功能却坏→stub 掉被验证的副作用→至少一条集成测试驱动真实链并断言可观测结果。
