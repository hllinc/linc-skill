# 需求澄清·现状盘点·范围界定手册（展开）

展开 SKILL.md §2.2–§2.5。三个阶段各自只填共享关闭表中自己的部分；产品意图与 P0 边界由人拍板，agent 只提候选。

## 2. 需求意图澄清

**何时进入：** 需求不清、需求对齐会前后、写 PRD 前补目标用户与约束、需要用户故事/验收标准/拷问问题池。

- 先定位意图：记录用户目标、目标用户、触发场景、成功标准；缺任一项就列为人类决策待关闭项，不自行补。
- 逐项检查需求合理性：问题是否真实、方案是否直接关联问题、有无更小替代、核心价值能否闭环、投入是否经济、失败代价是否可接受。
- 做一轮有边界的主动取证，再把权威冲突、额外授权、人类决策项升级出来。
- 拆用户路径：主路径、分支、异常、取消、退出、撤销都要有，不只主路径。
- 事实与假设分离：每条已知标来源，每条未知标 accountable owner；缺来源的事实交现状盘点，不自行推断。
- 代码、数据、配置等描述性证据只补事实，不裁决产品口径与承诺。
- 「非目标」在此为意图级：本轮不追求的目标、易被误解为目标而排除的诉求；「验收」在此为功能点的 pass/fail，不是切片验收边界。
- 每个功能点至少一个可观察的 pass/fail 验收条件，不复述功能名，不用「体验更好」类不可判定表述；安全命中项补负向验收。
- 讨论闭环分开记录：沟通记录、争议点、已决策、未决项、下一轮问题。
- 生成拷问问题池：每题带候选方案、推荐默认值、错判代价，供一问一答压力测试使用；本技能只出题与整理拷问结论，不做逐问过程。
- 追问最小化：先批量处理可自动项，只提出仍阻塞的人类决策问题，每题给候选、推荐、代价、accountable owner、受影响需求点；agent 维护完整机器账本，产品人员不逐格填。
- 更新需求点关闭表时只填用户价值、问题、方案关联、产品口径、路径、验收字段，逐字段记录关闭方式/来源、决策权与所需决策证据；只提出行状态候选，不得把整行设为 closed；只知 owner 无明确决定时保持 open/blocked。
- 自动填写仅限有可引用已批准 policy 的单个低风险非核心字段，且不得升级为核心承诺；无 policy 时保持 open 或转人类决策。
- 涉及身份、计费、配额、租户/用户隔离、权限、删除、覆盖时，逐项作答安全 4 问并写明所依据的规范文件名；无命中要显式记「无安全敏感输入」；凭记忆作答、未写来源、命中却记无命中均违规。
- 安全规范读取不可得时不得声称已读：写「不可得(原因)」，尽力作答，本节标 interim 并写解除方式，缺口连风险标签交风险路由决定是否接受推迟；推迟不等于关闭，正式关闭仍须真实读取后逐项重答。
- 安全命中后把风险标签与 gate 选择交风险路由；进入研发交付交回顶层工作流。
- PRD Ready 不由本技能判定；未关闭时只交接关闭表与下一动作；只有 lifecycle 判 Ready 后才转 PRD 成文。
- 产出固定模板：产品意图、目标用户/场景、已知事实(含来源)、未知/待确认(含 owner)、用户路径、非目标(意图级)、沟通记录/争议、已决/未决、拷问问题池、需求合理性六项、关闭表、验收点、安全 4 问、依据来源、下一步 owner；「依据来源」不得留空。
- 完成标准逐条可核，缺一条即 interim。

**硬性门禁（不满足不能继续）**
1. 产品意图、目标用户、成功标准三者均有记录，或明确列为人类决策待关闭项。
2. 每个功能点至少一个可观察 pass/fail 验收条件。
3. 已知/未知分离，每条已知有来源，每条未知有 accountable owner；用户路径含异常/取消/回退。
4. 关闭表无任何整行被设为 closed；自动填写项均能指出已批准 policy。
5. 安全 4 问：记「无命中」，或四项逐条作答 + 写明依据文件名；读取不可得时写「不可得(原因)」并标 interim。
6. 证据不足的结论不得写成事实；本技能不判 PRD Ready。

## 3. 需求现状盘点（as-is）

**何时进入：** 改需求前弄清现在怎么运作、已有什么能力、缺口在哪；选型/评估/替换/下线决策所依赖的现状事实取证；按当前代码说明某状态/数据如何产生与消费。

- 只描述现状，不下产品决策，不判断「应该怎么改」；描述性证据不裁决 should-be。
- 可用性证据不是选型结论：活跃度、最近提交、「跑得起来」「有 API」「另一候选已停更」只说明存在且可用，照记但不得推出「所以选它」。
- 盘点候选组件/服务时必记其自述定位（README 首句、manifest 描述）；查不到就写「自述定位未查到」并列已查来源，不得代拟。
- 层级归属分现状栏与目标栏：现状栏按部署配置、依赖图等有来源证据照记；目标栏仅当有来源的目标架构明确写到该候选时才填；「架构未确认」与「架构未涵盖该候选」分别记明，作为证据缺口交回决策 owner，不得推断补齐。
- 先判 current-state 三态并记录存在性检查范围；有新鲜权威基线时记「由权威基线满足」，权威基线不得记 N/A。
- 判 `not-applicable` 的全部前置：有边界的存在性检查、能证明净新增、不触及既有流程/权限/数据/API/规则/迁移/兼容/旧版本行为；任一不成立即不得判，判了要逐条写成立依据。
- 定义盘点对象：流程、页面、API、数据、规则、角色或能力边界。
- 做一轮有边界的主动取证：记录已查类别与未查类别及原因，不假设未授权的网络、生产或客户数据访问；未解析来源单独列出。
- 每条现状结论具名来源并标新旧与可信度；无来源的结论标未确认。
- 未查到 ≠ 不存在：正常取证后仍未查到的能力/接口/数据/权限/审核流/模型能力不得写成已确定字段，对应需求行不得 closed。
- 核验来源权威性、freshness、适用范围：同级权威产品来源冲突立即升级；新权威源替代旧非权威源时记录冲突处置与重开条件。
- 画用户路径与系统路径：入口、步骤、状态变化、异常/回退；页面/API/服务/数据/规则链路，不确定处标注。
- 缺口、冲突、风险三者分开列，不混进「已有能力」：与目标不匹配的空白、重复能力、规则矛盾、事实不足、过期来源、权限/数据/删除/覆盖风险。
- 代码里存在 ≠ 已部署启用；问线上是否启用要转可观测性，不在此下结论。
- 关闭表只以「证据推导」填 as-is 描述性事实或有效已批准规范来源授权范围内的字段，记录决策权、来源、推导、冲突处置、重开条件；只提出行状态候选，不得整行 closed。
- 涉及身份、计费、配额、租户/用户隔离、权限、删除、覆盖时逐项记录安全 4 问的现状答案并写明依据文件名；无命中显式记「无安全敏感输入」；读取不可得走「不可得(原因)」+ interim + 交风险路由推迟路径，推迟不等于关闭。
- 交接决策 owner：完整关闭表交回 lifecycle、意图澄清、范围界定、缺陷诊断或风险 gate。
- 产出固定模板：盘点对象、事实来源、用户路径、系统路径、已有能力、缺口/冲突、风险/不确定、未解析来源/未查类别及原因、关闭表、安全 4 问、依据来源、下一步 owner。
- 完成标准逐条可核，缺一条即 interim。

**硬性门禁（不满足不能继续）**
1. 每条现状结论有具名来源 + freshness + 可信度；已查与未查类别（及原因）都写出。
2. 不下产品决策；没有任何结论由活跃度、可运行性或「另一候选已停更」单独推出。
3. 候选组件必记自述定位或「未查到 + 已查来源」；层级归属现状/目标两栏分填，不得推断。
4. 三态判定已记录；判 not-applicable 时每条前置条件逐条写明依据。
5. 未查到不得写成不存在；关闭表只填证据推导字段，无整行 closed。
6. 安全 4 问逐项作答 + 依据文件名，或显式「无命中」；不可得时标 interim。

## 4. 需求范围界定（变更边界）

**何时进入：** 方向已定之后，界定本轮改哪些、不改哪些、影响谁、依赖什么、切几版、愿意花多少；MVP 边界、版本切片、兼容/回滚/降级边界、appetite/timebox。

- 前提是方向已定；方向未定先回意图澄清。
- 锁定目标与输入：引用已澄清需求或盘点事实；缺某条 as-is 事实不自动回现状盘点，标未确认、写缺口与取得方式、继续交付范围表；只有用户点名要现状清单或缺口大到范围表无法成立才交回，后者是人类决策。
- 受影响对象十类逐类过一遍：角色、页面、入口、API、数据、运营规则、通知、报表、权限、文档；不适用显式写「无」。
- in/out 写成可审查的行为边界，不用「优化体验」类不可判定标签。
- as-is 证据不裁决 should-be 范围：代码、数据、架构不能自行决定本轮改不改。
- P0 核心 in/out 由人类决策关闭；agent 不得决定产品目标、核心路径、成本级别或验收承诺。
- 「非目标」在此为变更级：明确不改、延后、保持兼容、无需迁移的对象；「验收」在此为每个切片的验收边界与不验收项。
- 切版本：P0/MVP、后续版本、迁移/兼容切片、回滚/降级边界分别列清。
- 先判 appetite 是否适用再记投入与取舍：任务要求投入决策或已有适用上限时记录已确认上限与超限可调范围；取舍未定保留已知上限、未知子项标 open、继续交付其余字段；不得自行砍核心范围、降低既有验收要求或承诺按期完成。
- 人工兜底只在业务连续性、降级或已批准决策确需时填写，不需要时写明依据，不为填表虚构人工接管。
- 仅做影响范围盘点、未涉投入决策时 appetite 可记 not-applicable；用户要求省略展示细节可从命，但已确认约束与未决事项保留在关闭表中，省略展示不等于撤销约束或关闭承诺。
- 标依赖：上游决策、外部系统、数据准备、设计、法务/运营/支持动作；标风险：权限、隔离、计费/配额、删除/覆盖、数据迁移、发布复杂度、跨团队/系统依赖。
- 每个切片写可观察的验收边界 **和** 不验收项；安全命中项的负向用例写进验收范围。
- 关闭表按复合字段子项补版本、范围、appetite、依赖、验收，逐项记录推导、决策权与决策证据；只能自动填写单个低风险、可逆的非核心展示/表达细节且需可引用已批准 policy；任一适用子项 open 时复合字段与整行保持 open/blocked。
- 涉及身份、计费、配额、租户/用户隔离、权限、删除、覆盖时逐项作答安全 4 问并写明依据文件名；无命中显式记「无安全敏感输入」；读取不可得走「不可得(原因)」+ interim + 交风险路由推迟路径，推迟不等于关闭。
- 安全命中后先让风险路由定级并选 gate；进入交付计划回顶层工作流；测试层/矩阵/CI gate 交测试策略；完整 PRD 需 lifecycle 已判 Ready。
- 产出固定模板：目标、In scope、Out of scope(变更级非目标)、受影响对象、版本切片、Appetite/timebox(适用性与依据)、依赖、风险点、验收范围(含不验收项)、关闭表、安全 4 问、依据来源、下一步 owner。
- 完成标准逐条可核，缺一条即 interim。

**硬性门禁（不满足不能继续）**
1. in/out 每一项都是可审查的行为边界，无模糊标签。
2. 受影响对象十类逐类过完，不适用显式写「无」。
3. 每个切片都有可观察验收边界和不验收项；安全命中的负向用例已在验收范围内。
4. P0 核心 in/out 标人类决策，未被 agent 自行关闭；as-is 证据未被用来裁决范围。
5. appetite 已判适用性：适用子项有决定或明确未决状态，不适用有依据；未知项不抹掉也不阻断其余材料。
6. 关闭表任一适用子项 open 时复合字段与整行保持 open/blocked；安全 4 问逐项作答 + 依据文件名或显式「无命中」。
