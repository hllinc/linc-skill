# Node/TypeScript 服务开发手册

## 1. 运行时与项目契约
- 动手前先读最近的 AGENTS 契约、package.json、锁文件、运行时版本文件、tsconfig、构建/测试脚本与部署清单，记下：支持与部署的 Node 主线、包管理器与权威锁文件、ESM/CJS 与 JS/TS 执行及类型检查路径、框架生命周期、验证命令、外部契约变更与非目标。
- 运行时版本以仓库与部署证据为准；.nvmrc、engines、镜像基础版本、CI 矩阵、生产运行时不一致时不得默默选一个。
- 新项目无契约时只选当前受支持的 Active/Maintenance LTS；不要硬编码 latest，也不要按奇偶数推断支持期，以官方发布计划为准。
- Current/Alpha 线仅用于明确的兼容或实验目标，且不得凭开发冒烟测试扩大生产支持声明。
- 库或共享包承诺版本区间时，最低与最高支持版本都要测；应用通常固定一条部署线，升级候选单独测。
- 编码前必须能写出契约检查点：运行时、包管理器、模块边界、类型路径、公共契约是否变更、最小必要兼容矩阵。
- 保持已定契约，除非显式迁移；Bun/Deno 语义不同，迁移是产品级决策而非直接替换。

## 2. 模块与配置
- 保留既有模块体系；新包必须显式设置 package.json#type，不依赖对含糊 .js 的语法探测。
- package exports 是公共兼容契约，发布库时从打包产物逐条测每个承诺的 import/require 路径；内部路径别名要有运行时支持而非仅编辑器/类型检查支持。
- 动态 import、顶层 await、JSON/原生模块、测试运行器、打包器与部署加载器行为要纳入兼容矩阵。
- TypeScript 只选一条明确路径：先编译再运行 / 运行时加载器 / Node 内置类型剥离 / 纯 JS，每条都要给对应证明。
- 内置类型剥离忽略 tsconfig、不做类型检查、不转换 enum/命名空间/参数属性/import 别名；必须另设真实的类型检查门禁。
- 配置在启动时解析并校验一次，向内传递类型化值，禁止在代码各处直接读 process.env。
- 分开做存在性、格式、范围、跨字段校验；错误信息可点名键名但不得回显密钥值。
- 明确默认值、env 文件、环境变量、flag、密钥挂载、远程配置的优先级；新出现的内置 flag 不是改优先级的许可。
- 构建期与运行期配置分开，容器注入与本地开发路径分别验证。
- 依赖变更保持最小并更新锁文件；CI 与验证用冻结安装；不切换包管理器、不重生成外来锁文件。
- 新增依赖要审维护状态、运行时支持、传递体积、原生构建/安装脚本、许可证，并先确认内置 API 是否已够用。
- 签名/来源只是来源证据，漏洞扫描不能证明依赖无恶意或漏洞路径可达；自动依赖升级不能仅因 CI 绿就接受，要审行为、变更日志、锁文件差异与回滚路径。

## 3. 异步生命周期与取消
- 先给工作分类：网络/异步 I/O 走事件循环原生异步 API；短 JS 变换走回调；CPU 密集 JS 走有界 worker_threads 池；阻塞/原生任务要量 libuv 池压力；大或无界负载走带背压的流。
- 长回调拖垮事件循环吞吐、长 libuv 任务饿死线程池，输入可控时两者都是 DoS 路径。
- 服务边界接受一个拥有者的取消/截止信号，并透传到每个支持的下游 API；优先复用已有 AbortSignal，合并调用方取消与超时时不丢原始原因。
- 只 race 一个超时而让数据库调用、fetch、流、worker、子进程继续跑，不算取消；必须 close/destroy/abort 底层资源，或写明无法停止并限制孤儿工作。
- 清理时移除监听器与定时器；unref 只在符合生命周期归属时用，不是取消工作的替代。
- 重试必须落在一个整体截止时间内且有界；非幂等副作用没有幂等契约不得重试。
- 请求上下文（关联/trace id、租户、截止、认证主体）放 AsyncLocalStorage，在请求/任务/消费者入口建立一次向内读取，不穿透每个签名也不放进程级可变量；不要手写 async_hooks 上下文机制。
- 无上下文时的行为按值所授权的东西定：诊断值可默认，租户/主体/权限范围缺失必须失败关闭，绝不裸解引用。
- 上下文不会自动跨 worker_threads 或子进程边界传播，未验证的边界要显式传值。
- 变长输入上的无界 Promise.all 换成仓库标准限流器/队列/批窗口；同时限制队列长度和 worker 数，并定义过载行为（拒绝、丢弃、持久延后或反压生产者）。
- 追踪在途工作归属以便关闭时等待或中止；脱管 promise 必须有显式监督者与错误汇；避免按请求起子进程或 worker，CPU 卸载要先量任务时长与传输成本再复用有界池。
- 出站 HTTP 客户端是有界资源：全局 dispatcher 在启动时刻意设置，替换视为全服务变更；每源连接数与源数量默认无界必须限制；连接/头/体超时都不是整体截止，整体截止来自调用方 AbortSignal；未消费的响应体占住连接，只要状态码也要消费或显式取消，并直接测试丢弃路径；默认值随版本漂移，以部署版本文档与实际接线为准。

## 4. 流与背压
- 大或无界数据一律用流；优先 node:stream/promises 的 pipeline 或既有等价物，让错误与拆卸沿链传播。
- 遵守 write 的背压/drain 语义，高水位按测量设定而非经验之谈。
- 流式只限制内存增长不限制总工作量，仍要设置负载/记录上限。
- 透传 abort 信号，并验证源错误、变换错误、目标错误、客户端断连、超时五种情况下的清理。
- 同一个 readable 不要混用 flowing 模式事件处理与 async 迭代，除非生命周期被刻意控制。
- 默认禁止整流缓冲、同步热路径 API、按请求起 worker/进程。

## 5. 优雅关闭
- 就绪与存活是不同契约；收到 SIGTERM 时按序：置就绪为 false 停止路由 → 停止接新工作 → 排空有界在途工作 → 中止自有后台循环与消费者 → 关闭数据库/队列/缓存/HTTP/worker/遥测资源 → 仅在文档化宽限期后强制终止。
- 只遵守一个文档化的关闭截止时间，升级连接（WebSocket 等）单独处理。
- server.close 与强制关连接语义随版本变化，要核对部署 Node 线、长连接/keep-alive 行为与编排器宽限期。
- 优先设置 process.exitCode 让自有刷写完成，只有可接受丢弃待处理异步工作时才立即 process.exit。
- 未知的 uncaughtException 与默认抛出的 unhandled rejection 视为致命，处理器只做同步清理/诊断后终止，不得从未定义状态恢复正常运行。
- 错误只在能做出有效决策的边界捕获（转换、按策略重试、补偿或失败），否则保留 cause 向上传播，在边界映射一次；禁止吞掉 rejection。
- 持久/任务状态每次转换只取一次时钟，领域时间按收到值记录不重盖；外部响应先做 schema 校验再映射，畸形上游负载必须成为带规范错误的持久化失败转换，而不是崩溃或静默默认值。

## 6. 性能
- 性能/可靠性主张必须有代表性负载加结果证据加因果证据；仅靠代码审视不能证明泄漏、卡顿或回归已修复，必须重跑复现器。
- 用代表性负载、并发、运行时 flag、依赖状态与预热复现；采集应用结果（延迟分布、吞吐、超时/错误率）加至少一个因果信号（CPU profile、事件循环延迟/利用率、池/队列深度、堆/GC、活跃资源）。
- 一次只改一个机制，同负载重跑，比较分布而非单次最快样本；负载下同时检查正确性与资源清理，更快但错或泄漏即回归。
- CPU 归因用 profile/火焰图，内存主张用堆/保留者证据；堆快照会停主线程且堆占用近似翻倍，不得在唯一生产实例上取，也不得暴露无鉴权的快照端点。
- 不加无观测需求的全局重试、投机缓存、通用基类层或进程级异常恢复。
- 优先显式依赖与启动接线而非可变进程级单例，使测试无需绑端口或改全局。

## 7. 诊断与验证
- 保留仓库现有运行器，node:test 是一等内置选项而非强制迁移目标；换运行器只能基于实际需求。
- 按行为选证明：领域逻辑直接单测不绑端口不改全局；HTTP/RPC 适配器做进程内集成测状态/schema/错误映射；数据库/队列/缓存适配器用真实协议或契约忠实替身；超时/取消用可控时间并断言底层工作已停止；流测背压、部分失败、断连、清理、大小上限；worker/后台任务测归属、重试/幂等、毒输入、关闭排空；进程生命周期用子进程测信号、退出码、就绪/排空截止；包边界在支持矩阵上启动/导入打包产物。
- 只 mock 窄的外部边界不 mock 被测实现；重置 mock 与定时器，避免跨测试进程全局污染；并发有意义时测顺序无关性，可疑抖动用例反复跑后再称稳定。
- 覆盖率是缺口探测器不是验收标准；保留既有阈值；内置覆盖率 flag 有版本差异，作为必需门禁前要在每个支持运行时上验证。
- 验证顺序由窄到宽：聚焦行为与失败路径测试 → 所触包的 lint/类型/检查 → 包/服务套件 → 构建/打包/启动检查 → 仓库必需门禁；相关时必须演练取消、畸形输入、清理与关闭。
- 对抗用例清单：大而合法输入；触发最坏解析/正则的畸形输入；下游永不响应或无视取消；客户端流中断连；队列到达上限；启动中与在途时收到关闭；worker 崩溃或返回不可序列化/超大结果；重试预算/截止耗尽。
- 诊断从证据起步：高 CPU/延迟看复现器与 CPU profile、事件循环与队列证据，不凭单个栈样本；事件循环卡顿看延迟/利用率与长回调归因，不看总 CPU；内存增长看堆/GC 趋势与保留对象对比，不看单个 RSS；进程不退出看活跃句柄与自有定时器/监听器/worker，不加强制 exit；线程池饿死先看负载类别与异步资源时长，不先加池大小；抖动测试反复隔离跑并捕获种子/时间/并发与泄漏资源，不盲目加超时。
- 证据要绑定候选提交与运行时；诊断命令失败、超时或无法附加是缺失证据不是干净结果。
- 验证记录按表输出：检查项、命令/探针、结果、SHA+Node 线；跳过、不可用、不确定与通过绝不合并成一个"绿"。
- 报告须列出运行时/包/模块契约、变更行为、保留边界、精确检查、测量、跳过项、版本假设与风险。

## 8. 安全
- 输入与复杂度：校验类型/形状/范围；限制头、体、解压、记录数、正则复杂度、递归与解析工作量；输入相关的长回调既是性能也是 DoS 风险。
- 注入与路径：数据库/进程用参数化 API，不拼 shell；规范化并约束文件系统路径，定义归档/符号链接行为。
- HTTP 边界：保持安全的解析器默认值，对不可信网络输入做 schema 校验，设置与框架/运行时匹配的显式超时与上限，不暴露框架诊断或原始错误。
- 出站访问：用户输入影响网络访问时校验目标与重定向，服务级保障靠平台出口控制。
- 密钥与日志：绝不记录凭据/令牌/原始敏感负载，在结构化日志边界脱敏并测试代表性失败路径。
- 依赖：审直接与传递变更、安装脚本、锁文件差异、已知公告、维护者/包身份与回滚；npm audit 只是一个信号不是通过/失败证明。
- 运行时容器化：Node 权限模型可削减文件/网络/进程/插件/worker 能力，需在部署环境验证 flag 与框架需求；它是纵深防御，不能让进程内恶意代码变得可信，也不是完整沙箱。
- 原型/对象风险：只接受预期键，用 schema 校验，不对不可信对象做不安全递归合并，保持框架/运行时打补丁。
